# 内容与单元规范 · 0.1.0

## 读者承诺

普通人是起点，不默认编程、终端或账号知识。零基础不代表产品一定免费、无代码或全国可用；真实门槛须说明。

系统书默认两段：普及段讲产品、用途、限制、适用人群；分水岭说明继续所需条件、补课和替代路径，允许读者停止；深入段按前置逐步完成任务。分水岭不固定章号，普及段不固定篇幅。单篇教程有目标、前置、步骤、成功标志、排查和后续选择即可，无须凑三章。

book.yaml 是顺序、section、depth、prerequisites、features、facts、derived_from 的唯一来源。正文不复制 YAML。depth 0 无专业前置、1 需要指定基础训练、2 需要指定编程/系统知识；深度允许回落，只检查前置满足及门槛说明。

## 写作

新概念、按键、路径、缩写首次出现即时解释。首次独立成功路径逐步写清：开始条件、动作、预期结果、失败处理。承诺多平台则分别写和验证。不能用“后面会讲”替代本步必需知识。

每章保留小结、动手、卡住了；动手就是自测，不安排干瘪测验题。可选支线不承载后续必需知识。示意对话标为示意；实际结果来自记录。对话中 **你** 加粗，助手使用真实产品名称且不加粗。

正文用生活任务，必要技术例子补齐前置。不要用“众所周知、显而易见、很简单”掩盖步骤。完整配置放附录或可下载材料；正文解释作用和最小必要片段。术语先查本书术语表，需要新增先登记。

## 单章作业

1. 备料：目标、前置、术语、事实、底稿和未知项。
2. 起草：解释、任务、排查、自检；不伪造实测。
3. 固定受审稿：先提交源稿，再写独立检查文件引用该提交。
4. 编辑复核：当前引擎或人工检查逻辑、遗漏、表达与读者门槛；另一实际引擎交叉审核仅在作者手动触发时执行，未触发不影响后续步骤。
5. 实测：按承诺环境跑步骤，记录真实输入、结果和失败。
6. 修订复核：改步骤、命令、条件或结果则重测相应路径。
7. 整合：更新结构和生成物，检查公开摘要与当前稿对应。
8. 交接：保存完成项、待做项和下一步。

样章确定语言和颗粒度后，常规章节不逐章重新立项。旧作品不为套新模板而自动重排或改写。
