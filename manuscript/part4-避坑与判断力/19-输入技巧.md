## 19.1 `!` 快跑 shell 命令（已在 Ch 18 提过，这里说透）

### 用法

提示符处**直接 `!` 开头**敲命令：

```
!git status
```

效果：Claude Code 跑这个命令，**输出进上下文**让 Claude 看到。

### 为什么值得单独用

- **提供上下文**："先给 Claude 看 git 状态再讨论怎么 commit"——比你口述更精准
- **避免中断流程**：不用切到另一个终端跑了再描述给 Claude

### 常用的 `!` 命令

| 命令 | 干什么 |
|-----|-------|
| `!ls` / `!ls -la` | 看当前文件夹 |
| `!pwd` | 看当前在哪 |
| `!git status` / `!git log -n 5` | 看 git 状态 / 最近 5 次提交 |
| `!cat 文件名` | 把文件内容贴给 Claude（小文件可以这样，大文件用 @） |
| `!date` | 让 Claude 知道"今天是几月几号" |

### 和 Claude 主动跑命令的区别

- `!command`：**你主动跑**，绕过权限询问（但仍在 Claude Code 的沙箱里）
- Claude 要跑命令：它会先说"我要跑 `X`，同意吗？"—— 走权限弹窗

**用 `!` 的前提**：这个命令你**百分之百确定安全**。

## 19.2 `@` 精准引用——进阶用法

基础用法 Ch 5 讲过。**三个进阶技巧**：

### 技巧 1：Tab 自动补全

打 `@` 后开始打路径，**按 Tab**：
- 自动补全文件名
- 如果路径有多个匹配，再按 Tab 会轮流显示

**省时**：不用手打长路径、不会拼错文件名。

### 技巧 2：引用多个文件

```
@a.md @b.md 对比这两份笔记的相同点和差异
```

Claude 会**一次性读取多个**。

**注意**：`@` 的文件越多 / 越大，Ctx 消耗越快（见 Ch 12）。**一次 3-5 个是舒适区**。

### 技巧 3：引用文件的特定段（更精准）

**不要**直接 `@巨型文件.md`——先自己**定位到关心的区间**：

```
@长文档.md 第 3 节"数据流"那段大概 100-150 行左右，帮我改得更简洁
```

Claude 会直接定位到那段，不会把几万字全读进来。

（更准一点的话：有些版本支持 `@文件#锚点` 或 `@文件:50-80` 语法——查 `/help` 看你的版本是否支持。）

## 19.3 图片 / 截图输入

Claude 能**看图**——这是很多人不知道的利器。

### 怎么输入图片

**方式 1：直接粘贴（最快）**
- 系统截图（Mac `Cmd+Shift+4`、Windows `Win+Shift+S`）
- **直接 `Cmd+V` / `Ctrl+V`** 粘贴到 Claude Code 输入框
- Claude Code 会显示 `[image 1]` 之类的占位
- 发出去，Claude 看到图

**方式 2：`@` 引用图片文件**
```
@~/Desktop/截图.png 帮我看这张图里的错误信息
```

### 什么场景该用图

- **报错截图**：你看不懂某个报错窗口——截图比打字描述准
- **UI 设计稿**：让 Claude 按稿子写代码
- **表格照片**：把纸上的表格录进电脑
- **图表**：让 Claude 解读数据图
- **手写笔记**：转成电子版

### 注意事项

- 图片**也占上下文**（且占不少）——不要一次塞十张图
- **不要传含个人隐私的图**（身份证、聊天截图等）——回 Ch 11 复习红线
- 图片识别有**误读风险**：手写字 / 模糊文字容易错——**关键信息自己核对**

### 一个真实场景

```
你：（截图了一个 Python 报错）
    这个错是什么意思？怎么修？
Claude：（识别图里的 stack trace）
    这是一个 AttributeError，在 line 42 的 ...
    可能原因：...
    修复方案：...
```

**比你打字复述报错信息快 10 倍**。

## 19.4 多行输入——长提示词的正确姿势

### 问题

复杂任务需要多行提示词：

```
我要做 XXX
要求：
1. ...
2. ...
3. ...
限制：...
```

默认按 Enter 就发了——你只能打到第一行就被迫发出。

### 解决

**Shift+Enter**（大部分终端）—— 换行不发送。

完整流程：

1. 敲第一行
2. **Shift+Enter** 换行
3. 敲第二行
4. **Shift+Enter** 换行
5. ... 都敲完
6. **Enter** 发送

### 替代方式

某些终端不支持 Shift+Enter，试：
- **Option+Enter**（Mac）
- **Alt+Enter**（Windows / Linux）
- 或使用粘贴——在别处写完多行文字，整体粘进来

### 超长提示词：用文件

如果你要发一个**几百字的复杂提示**，最佳做法：

1. 在文本编辑器里**把提示词写成一个 `.md` 文件**
2. Claude Code 里 `@prompt.md`
3. 后面加一句 "按上面这份说明做"

**为什么这样更好**：
- 你可以反复调整 prompt 文件，不怕每次重敲
- 可以**复用**——下次类似任务直接 `@` 同一个文件
- 多人协作时能**共享 prompt 模板**

## 19.5 历史回溯

### 上 / 下键翻历史

在输入框里按 **↑**：逐条翻看你之前发过的消息。

**什么时候用**：
- 刚才发的那句话想改一下重发——按 ↑ 取回来改
- 翻"几轮前我具体说了什么"
- 复用之前的模板化提示

### 搜索历史

某些终端支持 **Ctrl+R** 搜索——打几个关键词，找到历史消息。

**注意**：历史只在**当次会话内有效**。`/clear` 或退出后清空。

### 粘贴失败时的历史回溯

一种常见场景：
- 你粘贴了一大段文字
- Enter 发送时发现其中有一处错
- `/rewind` 回到发送前
- **按 ↑** 取回那段文字
- 改好后重发

比"从头写一遍"快很多。

## 19.6 粘贴大段文字的正确姿势

### 问题

你从网页 / 文档里复制一段话，粘进 Claude Code。结果：
- 格式乱了（换行错位 / 特殊字符）
- 太长，直接爆上下文
- 粘贴过程卡顿

### 解决方案

**方案 A：小段（< 10 行）直接粘**
- 正常 Cmd+V / Ctrl+V
- 发送前检查一下排版

**方案 B：中段（10-100 行）用多行输入**
- 先打一句引子："以下是我要讨论的段落："
- Shift+Enter 换行
- 粘贴
- Enter 发送

**方案 C：大段（> 100 行 / 很长的文档）保存为文件再 `@`**
- 新建 `~/Desktop/待处理.md`
- 把内容保存进去
- Claude Code 里 `@~/Desktop/待处理.md`

### 大段文字的两个陷阱

1. **意外的 Enter**：粘贴时某些行结尾是 Enter，可能触发发送——**先粘到单独的文本编辑器整理再二次粘到 Claude Code**
2. **隐藏格式**：从网页复制的文字可能带格式标记（HTML），Claude 会读到"干扰文本"——**粘进 Markdown 文件先"洗"一遍，再 `@`**

## 本章小结

- `!command` 快跑 shell 命令（你确定安全时），输出给 Claude 当上下文

- **多行输入用 Shift+Enter / Option+Enter**；超长 prompt 用文件 `@`
- **↑/↓ 翻历史**；大段粘贴的三档方案（< 10 / 10-100 / 100+）

## 如果你卡住了

**症状 A：Shift+Enter 按下直接发送了**
- 原因：某些终端仅认 Option+Enter 或 Alt+Enter。
- 解决：都试一下；或用"先写文件再 `@`"代替长提示词输入。

**症状 B：粘贴图片没反应**
- 原因：某些终端不支持图片粘贴。
- 解决：**保存图片到本地文件夹再 `@` 路径**，效果一样。

**症状 C：粘贴大段文字后 Claude 回复乱码 / 看不懂**
- 原因：文字里有隐藏格式 / 特殊字符。
- 解决：**先粘到 VS Code / 记事本等纯文本编辑器**，保存成 `.md` 文件，再 `@` 进来。

## 🌿 支线 19.A：键盘快捷键收藏单

> **这段讲什么**：Claude Code 里不只 `@`、`!`，还有一堆编辑快捷键。
> **什么时候回头读**：你用了一段时间后想提效时。

### 光标移动

| 键 | 效果 |
|---|------|
| **Ctrl+A** | 光标跳到行首 |
| **Ctrl+E** | 光标跳到行尾 |
| **Option+←** / **Option+→** | 跳一个词（Mac） |
| **Alt+←** / **Alt+→** | 跳一个词（Windows） |

### 删除

| 键 | 效果 |
|---|------|
| **Ctrl+U** | 删除从光标到行首的内容 |
| **Ctrl+K** | 删除从光标到行尾 |
| **Option+Delete** | 删一个词（Mac） |
| **Ctrl+Backspace** | 删一个词（Windows） |

### 会话控制

| 键 | 效果 |
|---|------|
| **Ctrl+C** | 中断当前运行（Claude 思考中按它会停止） |
| **Ctrl+C Ctrl+C**（两下） | 退出 Claude Code |
| **Esc Esc** | 快速撤销（见 Ch 9） |

## 🌿 支线 19.B：输入模板库的搭建

> **这段讲什么**：任务 2 只建了一个模板，展开讲如何系统化建"prompt 库"。
> **什么时候回头读**：你开始在多种任务上反复用同类提示时。

### 文件夹结构建议

```
~/Desktop/prompts/
├── 写作/
│   ├── 日报润色.md
│   ├── 周报生成.md
│   └── 邮件草稿.md
├── 整理/
│   ├── 截图重命名.md
│   └── 笔记归档.md
├── 编程/（如果你会点）
│   ├── 代码审查.md
│   └── 写测试.md
└── README.md   # 一张目录索引
```

### 每个模板文件的格式

```markdown
# 任务：日报润色

## 输入
我会给你一份原始日报（纯流水账）。

## 输出要求
- 保留所有真实事项
- 合并相近事项（同一天两次"改文档"合并）
- 每项 30 字以内
- 顺序按重要性，不按时间

## 禁忌
- 不要编造事项
- 不要加 emoji

## 风格示例
- ❌ "今天早上 9 点开会讨论了项目进度"
- ✅ "项目会议：Q2 目标确认"
```

### 怎么用

```
@prompts/写作/日报润色.md @今天的日报.md 按模板走
```

### 维护节奏

- **每次做完任务回头看**：模板能不能更好？更新
- **每月扫一遍**：哪些没用到的删掉
- **存进 git**（或云盘同步）：防止丢失

这一套建立起来之后，**日常任务的提示词成本降到接近零**——你花 2 分钟填具体内容，模板把其余都包了。
