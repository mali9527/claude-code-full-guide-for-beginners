# 第 3 章：你的第一次对话

> **本章在全书的位置**：第一部分 · 第 3 章 / 预估阅读+动手时长：**主线 30-40 分钟 + 支线 10-15 分钟**
>
> **前置章节**：第 1 章（用终端）+ 第 2 章（装 Claude Code）
>
> **学完能做什么（主线）**：能进入一个工作文件夹启动 Claude Code，看懂它的界面，发消息、让它读文件、干净退出，并在下次进同一个文件夹时继续之前的对话。

---

## 开场三问

- **你会遇到什么问题**：装好了 Claude Code，打开它一脸懵——界面上每个东西是什么、该怎么开始说话。
- **不读这章会踩什么坑**：不知道要先 `cd` 到对应文件夹再启动（结果 Claude 看不到你的文件）；不知道怎么让它读文件；不知道怎么退出或怎么继续之前的对话。
- **读完你会多会什么事**：能在任意文件夹启动 Claude Code，顺畅地和它对话、给它看文件、干净退出；下次还能接着上次聊。

## 3.1 先准备一个"练习文件夹"

Claude Code 是**按文件夹来工作的**——你在哪个文件夹启动它，它的"视野"就限制在这个文件夹里。它只能看见、只能改这个文件夹里的东西（除非你明确告诉它去别处）。

> 💡 **为什么这样设计**：这是**一种安全保护**。避免你在"系统文件夹"里一启动 Claude Code，它就可能动到操作系统重要文件。你先 `cd` 到你想让它干活的地方，它就只在那儿活动。

### 动手建一个练习文件夹

我们先建一个专门用来跟着本书练习的文件夹——叫 `ccguide-练习` 放在桌面。

**步骤 1**：在桌面右键 → 新建文件夹 → 命名 `ccguide-练习`（用图形界面就行）。

**步骤 2**：在这个文件夹里建一个简单的测试文件。方法：
- **Mac**：双击进入文件夹 → 右键空白处 → **新建文件**（如果没这项，可以用 Finder 的"新建文稿"或者下面用终端建）
- **Windows**：双击进入文件夹 → 右键空白处 → **新建 → 文本文档** → 起名 `笔记.txt`

文件里随便写几句话，比如：
```
今天的待办：
- 买菜
- 给妈打电话
- 写周报
```

保存。这个文件等会儿让 Claude 读。

## 3.2 进入工作文件夹再启动

打开终端，**先 `cd` 到你刚建的文件夹**，再启动 Claude Code。

```
cd ~/Desktop/ccguide-练习
claude
```

第一行把你"搬"进练习文件夹，第二行启动 Claude Code。

**你会看到**：

```
╭───────────────────────────────────────╮
│ ✻ Welcome to Claude Code              │
│                                       │
│ /help for help, /status for status   │
│                                       │
│ cwd: /Users/你的名字/Desktop/ccguide-练习 │
╰───────────────────────────────────────╯

>
```

📌 **重点看那行 `cwd:`（current working directory = 当前工作目录）**——它必须指向你刚建的 `ccguide-练习`。如果不是，说明你忘了 `cd`，按 `Ctrl+C` 退出，重新 `cd` 后再 `claude`。

⚠️ **永远先 `cd` 再 `claude`**。这是本书反复强调的第一个好习惯。

## 3.3 认识 Claude Code 的界面

Claude Code 启动后，你的终端变成了下面几个区域——熟悉它们能让你少走弯路。

```
╭───────────────────────────────────────╮
│ ✻ Welcome to Claude Code              │  ← ① 欢迎横幅
│ ...                                   │
│ cwd: /path/to/你的文件夹               │
╰───────────────────────────────────────╯

（对话历史在这里展开）                      ← ② 消息区

                                          ← ③ 状态栏（可能有）

>                                         ← ④ 输入框
```

### ① 欢迎横幅

第一次启动时出现，显示版本号、工作目录、可用的快捷提示。之后对话起来就会被滚上去看不到了。

### ② 消息区

所有的对话（你说的话、Claude 的回复、权限提示、工具调用提示）都在这里按时间顺序往下堆。

### ③ 状态栏（在一些版本里位于输入框上方）

通常显示：
- 当前用的是哪个模型（Sonnet / Opus / Haiku）
- 当前对话用了多少**上下文**（Context）——形如 `Ctx: 12%`，这个以后超级重要（第 12 章专讲）
- 有时还有预估成本

💡 **状态栏的更多细节**——见 🌿 支线 3.B。

### ④ 输入框

最下面那个 `>`，后面闪光标的地方——**这是你打字的地方**。
- 打字 + 回车 = 发送
- **Ctrl+C** 按两次 = 退出 Claude Code
- **Shift+回车** = 换行（消息里想打多行）

## 3.4 发第一条消息，让它读一个文件

### 发一条打招呼

在输入框里打：

```
你好，简单说一下你是什么、能做什么。
```

按回车。

**你会看到**：Claude 开始一行一行输出回复——一般是一段简短介绍。**你不需要打断它**，等它自己说完。说完后光标回到输入框，等你下一句。

📌 **这种一来一回就叫"对话"**。你说一句、它回一次、然后等你下一句。中间它不会主动说话。

### 让它读你之前建的笔记文件

在输入框里打：

```
@笔记.txt 这个文件里写了什么？用 3 句话概括。
```

按回车。

**关键符号**：`@`——这是 Claude Code 的"**引用文件**"符号。打 `@` 后跟文件名，Claude 就会**把这个文件读进对话**。你不用自己复制粘贴文件内容。

> 💡 **生活化比喻**：`@笔记.txt` 就像给秘书递过一页纸说"看这张"。和你说"帮我看一下桌上那份文件"不同——`@` 是精确指向。

**你会看到**：Claude 会先告诉你它读了 `笔记.txt`（可能会简短复述你写的内容），然后给出三句话的概括。

### 让它改这个文件（初尝权限机制）

再试一句：

```
@笔记.txt 把这份待办清单的每一条前面加上编号 1、2、3。
```

按回车。

**你会看到**：Claude **不会直接动文件**。它会显示一个 **diff**（修改对比）——左边旧内容、右边它想改成的样子，然后弹出一个选项让你选：

```
Do you want to apply this change?
❯ Yes
  Yes, and allow similar changes for the rest of this session
  No, tell Claude what to do differently
```

（选项用**↑↓方向键**选，**回车**确认）

📌 **这就是 Claude Code 最重要的安全机制**：改文件、跑命令之前都会问你。你选 Yes 它才会真的改。第 6 章和第 7 章会把这套机制彻底讲透；本章先体验一下。

选 **Yes** 回车。Claude 会改完文件，并告诉你改完了。

**去图形界面打开 `笔记.txt` 看一眼**——内容应该真的被编了号。这就是 Claude Code 在干活的样子。

## 3.5 退出，并在下次继续

### 干净退出

两种方式：

- 按 `Ctrl + C` **两次**（按一下、松开、再按一下）——Claude Code 会确认并退出
- 或者在输入框里打 `/exit` 按回车

你会回到你原来的终端提示符（`%` 或 `>`）。

### 下次怎么继续

下次你想接着用，只需要：

```
cd ~/Desktop/ccguide-练习
claude
```

**注意**：直接 `claude` 启动的是**全新对话**——之前的对话内容 Claude 不记得了。

如果你想**接着上次聊**（保留之前的对话上下文），启动时加一个参数：

```
claude -c
```

或者：

```
claude --continue
```

`-c` / `--continue` 意思是 "continue the previous session"（继续上次会话）。

💡 **选哪个？**
- **新任务、新话题** → 直接 `claude`（开新对话，也方便让 Claude 轻装上阵）
- **接着上次没完的事** → `claude -c`

第 12 章会解释为什么新任务最好新开对话（涉及"上下文"管理）。现在先记住这两种启动方式。

💡 **还有 `claude --resume` 选特定历史对话**——见 🌿 支线 3.A。

## 本章小结

- Claude Code **按文件夹工作**——永远**先 `cd` 到工作文件夹再 `claude`**
- 启动后界面有 4 块：欢迎横幅 / 消息区 / 状态栏 / 输入框
- `@文件名` = 让 Claude 读这个文件
- **改文件前 Claude 会显示 diff 并问你，选 Yes 才真改**——这是核心安全机制
- 退出：`Ctrl+C` 两次，或 `/exit`
- 下次继续上次对话：`claude -c`（新话题就直接 `claude`）

## 动手任务

### 任务 1：建练习文件夹并启动（3 分钟）

**步骤**：
1. 桌面建文件夹 `ccguide-练习`（若已建跳过）
2. 里面建文件 `笔记.txt`，写 3 条任意内容
3. 终端 `cd ~/Desktop/ccguide-练习`
4. `claude` 启动

**成功标志**：启动画面里 `cwd:` 指向 `ccguide-练习`。

### 任务 2：让它读并概括（3 分钟）

**步骤**：在输入框打 `@笔记.txt 用一句话概括这份内容`，回车。
**成功标志**：Claude 返回一句符合内容的概括。

### 任务 3：让它改并审核（5 分钟）

**步骤**：
1. 输入 `@笔记.txt 帮我在每行前加一个 ☐ 符号（作为待办框）`
2. Claude 显示 diff 和确认选项 → 选 **Yes** 回车
3. **切到图形界面**打开 `笔记.txt` 看结果

**成功标志**：文件里每行前面真的多了 `☐`。

### 任务 4：退出后再用 -c 继续（3 分钟）

**步骤**：
1. `Ctrl+C` 两次退出
2. 终端里 `claude -c`（或 `claude --continue`）
3. 问它："**刚才我们做了什么？**"

**成功标志**：Claude 能回忆起刚才读过 `笔记.txt` 并改过内容。

## 如果你卡住了

**症状 A：启动后 `cwd:` 不是你建的练习文件夹**
- 原因：忘了 `cd`，或 `cd` 路径写错
- 解决：`Ctrl+C` 两次退出 → `pwd` 确认在哪 → `cd ~/Desktop/ccguide-练习` 后重新 `claude`

**症状 B：打 `@笔记.txt` 后 Claude 说找不到这个文件**
- 原因：文件名对不上（大小写、扩展名、是否真在这个文件夹）
- 解决：退出 Claude Code，`ls` 看这个文件夹里实际有什么；对照文件名精确重新试

**症状 C：Claude 改文件后选了 Yes，但文件内容没变**
- 原因：极少见的文件权限问题，或图形界面没刷新
- 解决：先在图形界面关闭 `笔记.txt` 再重新打开；还不行就 `ls -la`（Mac）/ `ls -Force`（Windows）看文件有没有被锁

**症状 D：`claude -c` 说没有可继续的对话**
- 原因：你从上次对话后换了文件夹——会话是按文件夹记录的
- 解决：确认当前在上次同一个文件夹里；或用 `claude --resume` 从列表里选（见支线 3.A）

## 🌿 支线 3.A：用 `--resume` 从历史对话里挑一个继续

> **这段讲什么**：`claude -c` 是"接上最近那次"，但如果你上周、上上周有几次对话都想回去看，需要另一个命令。
> **什么时候回头读**：你用了一两周发现自己在同一个文件夹有多次对话想翻出来的时候。

启动时加 `--resume`（或简写 `-r`）：

```
claude --resume
```

Claude Code 会弹出一个**历史对话列表**，按时间倒序列出你在当前文件夹的所有会话。用**↑↓方向键**选，**回车**进入。

每条列表项通常显示：
- 开始时间
- 消息数
- 第一条消息的前几个字（帮你认出是哪次聊的什么）

**`-c` vs `--resume` 一句话**：
- `-c` = 接最近那次
- `--resume` = 挑一次

⚠️ **跨文件夹不通**：每个文件夹有自己的对话历史。在 `练习A` 文件夹里聊的，到 `练习B` 里 `--resume` 是看不到的。

## 🌿 支线 3.B：状态栏到底在告诉你什么

> **这段讲什么**：Claude Code 屏幕上那些数字（`Ctx: 12%`、`Sonnet`、成本）具体含义。
> **什么时候回头读**：你发现状态栏在变数字、好奇那是啥。第 12 章会专门讲上下文（context），15 章讲模型和成本。

典型状态栏（随版本略有差异）：

```
● Sonnet 4.6  |  Ctx: 23% used  |  $0.12
```

分三段：

### ① 当前用的模型

- **Sonnet**：默认，性价比最高，适合 80% 场景
- **Opus**：更聪明、更贵，适合复杂任务
- **Haiku**：最快最便宜，适合简单任务

切换用 `/model` 命令（第 15 章详解）。

### ② Ctx: XX% used（上下文占用百分比）

这是**整本书最重要的一个数字**。它告诉你 Claude 这次对话的"短期记忆"用掉了多少。

- **50% 以下**：健康
- **70% 左右**：考虑用 `/compact` 压一下（让 Claude 把对话浓缩）
- **90%+**：必须 `/compact` 或 `/clear`，不然回复质量会明显下降

详细机制第 12 章专讲。**现在只需知道这个数字存在**，平时扫一眼。

### ③ 成本预估（`$` 数字）

当前这次对话累计花了多少钱（订阅用户显示相对占用、API 用户显示美元）。

- 免费额度用户：通常看不到 `$`，会看到额度余量
- API 用户：看 `$` 实际金额
- Pro/Max 订阅用户：看占你本月配额的比例

💡 **新手先不用操心这个数字**——默认 Sonnet 跑日常任务，一次对话通常几分到一毛几人民币的量级。详见第 15 章。
