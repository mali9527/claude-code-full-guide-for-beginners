## 开场三问

- **你会遇到什么问题**：复杂任务不知道怎么下手——直接让 Claude 改怕改错；改到一半发现方向错了不知道怎么回到起点。

## 9.1 安全网三件套——先认一下

Claude Code 给了你三个层级的保护：

| 工具 | 什么时候用 | 保护范围 |
|------|----------|---------|
| **`/plan`（计划模式）** | 任务开始前 | 让 Claude 只规划不动手——**根本不给它出错的机会** |
| **Esc Esc（两次 Esc）** | 刚做完一步发现不对 | 一键撤销**最近一个操作** |
| **`/rewind`（精确回退）** | 想回到更早的某个时刻 | 按检查点列表挑一个时间点回退（对话 + 文件都恢复） |

**三层保护的关系**：

```
最前面：/plan       → 尽量不让出事
中间：  Esc Esc     → 刚出事立刻救
事后：  /rewind     → 已经过了几步也能救
```

下面一个个讲清楚。

## 9.2 /plan 计划模式——让 Claude 只看不动

### 是什么

`/plan` 是一种**权限模式**（第 7 章提过）——在这个模式下：

- ✅ Claude 可以**读文件**、**分析**、**思考方案**、**给你方案**
- ❌ Claude **不能改任何文件**、**不能跑会改东西的命令**

它只能**说话**，不能**动手**。

### 什么时候值得先 `/plan`

- **复杂任务**：涉及多文件、多步骤、你没有把握
- **陌生项目**：你自己都没看过的代码/文件夹，先让它探查
- **高风险改动**：改生产配置、动重要数据前
- **你拿不准方案**：不知道是方案 A 好还是方案 B 好，让它两个都分析

> 💡 **反面**：简单明确的改动（"把这个文件里'foo'全换成'bar'"）**不用 `/plan`**，直接做就行。

### 怎么用

**方式 A：启动时进入**

```
claude --permission-mode plan
```

整个会话都是计划模式。

**方式 B：会话中切换**

对话里打：

```
/plan
```

切进计划模式。

**方式 C：切回来做事**

计划结束、方案定了后：

```
/permissions
```

切回默认模式（acceptEdits 也行），让 Claude 执行方案。

### 一个典型的 plan → execute 流程

```
（计划模式下）
你：@src/ 帮我看这个项目整体架构，分析一下如果我想加一个"用户反馈"功能，要改哪些文件
Claude：（读文件、分析）我看到这个项目是 ... 要加"用户反馈"，建议改以下文件：
  - A.tsx（新增表单）
  - B.ts（API 接口）
  - C.md（文档更新）
  步骤：...

你：方案看起来可行。把 A 和 B 按这个方案先做，C 我自己来。

（切回默认模式）
/permissions → 选默认

你：按刚才的方案开始改 A 和 B
Claude：（生成 diff，正常审核循环）
```

这种"**先规划后执行**"的流程叫 **plan → execute**，本书后面多处推荐。

## 9.3 Esc Esc——快速撤销最近一步

### 是什么

连按**两次 Esc 键**（键盘左上角 Escape）——一次、松开、再一次——触发**快速撤销**。

作用：**回到上一个检查点**（通常是你做最近一次改动之前的状态）。

### 什么时候用

- 刚让 Claude 改了个文件，打开看发现改坏了
- 刚跑了个命令，效果不对
- 你刚发了条消息但想反悔（退回到发之前）

### 一个典型场景

```
你：@config.json 把 port 从 8080 改成 9090
Claude：[生成 diff] ...
你：Yes
Claude：改好了。
你：（打开文件看）哦不，我意思是 port 不动，改的是 host——赶紧撤销

→ 按两次 Esc

你：回到改之前了。重新说：@config.json 把 host 从 localhost 改成 127.0.0.1
```

一次 Esc Esc 省了你手动恢复的麻烦。

### 和 `/rewind` 的区别

**Esc Esc** = "回到上一步"（快）
**/rewind** = "从历史检查点列表里挑一个"（灵活）

日常 90% 场景 Esc Esc 就够了。

## 9.4 /rewind——精确回到历史检查点

### 是什么

在对话里打：

```
/rewind
```

会弹出一个**检查点列表**——Claude Code 在对话过程中自动记录的"状态快照"。每个检查点通常对应：

- 你发出了一条消息
- Claude 完成了一次工具调用（读文件、改文件、跑命令）

你用方向键选一个检查点，回车确认。

### 你能恢复什么

`/rewind` 回退的是 **Claude Code 会话状态**：
- ✅ 对话历史（消息会被回退到那个时刻）
- ✅ Claude 在**本次会话中**改过的文件（**恢复到检查点时的内容**）
- ❌ **不会**影响你手动（在图形界面或其他终端）改过的文件
- ❌ **不会**影响 Claude 跑命令改过的系统设置（比如装的软件）

### 选"恢复代码 + 对话"还是"只恢复对话"

有些版本的 `/rewind` 允许你选：

| 选项 | 效果 |
|------|------|
| **恢复对话 + 文件** | 对话和 Claude 改过的文件都回到检查点 |
| **只恢复对话** | 文件不动，只把对话历史回退（适合你想"保留改动但换个思路重来"） |

新手默认选"恢复对话 + 文件"。

### 一个典型场景

```
[30 分钟前] 你让 Claude 改了 A、B、C 三个文件
[15 分钟前] 你又改了 D、E、F
[现在] 你发现从改 D 开始方向就不对了，想退回到只改 A/B/C 的状态

→ /rewind
→ 列表里找到"改 D 之前"的那个检查点
→ 回车确认

现在：A/B/C 的改动保留、D/E/F 的改动消失、对话回到改 D 前的瞬间。
```

你可以**基于那个时刻重新决定**怎么继续。

## 9.5 三件套和 git 的关系

如果你已经在用 git（代码版本控制），可能会问：**"有 git 了还要这三个吗？"**

答案：**都要。它们是不同层级的保护**。

| 工具 | 作用范围 | 粒度 |
|------|---------|-----|
| **Claude Code 安全网** | 一次 Claude Code 会话内 | 按"消息级"——细到每一条你发的消息 |
| **git** | 你整个项目的版本历史 | 按"提交级"——你 commit 一次就是一个节点 |
| **编辑器 Ctrl+Z** | 单个文件在单次编辑中的修改 | 字符级——最细 |
| **系统备份**（Time Machine / 文件历史） | 全盘 | 按天/小时的快照 |

**搭配建议**：

1. **开始任务前 `git commit` 一下** → 有个"干净基线"
2. **任务中用 `/plan` / Esc Esc / `/rewind`** → 在 Claude Code 会话内快速回退
3. **任务完成后 `git commit`** → 新的"干净基线"
4. **过几天回头看发现有问题** → `git revert` 或从备份恢复

这样你有**四层保护**，几乎不可能"永久改坏"一个文件。

> 💡 **不懂 git 也没关系**——Ch 25（团队协作基础）会从零讲 git 基础。**现在记住**：Claude Code 的三件套是"会话内的即时回退"，git 是"跨会话的长期版本管理"。

## 本章小结

- **安全网三件套**：`/plan`（不让出事）+ Esc Esc（立刻救）+ `/rewind`（事后救）
- **`/plan` 计划模式**：只读不写，适合复杂 / 陌生 / 高风险任务；plan → execute 是推荐流程
- **Esc Esc**：回退最近一步，90% 日常场景够用
- **`/rewind`**：按检查点列表挑时间点回退，对话 + 文件都恢复
- **和 git 配合**：三件套管会话内、git 管跨会话，多层保护

## 动手任务

### 任务 1：用 plan 模式规划一个任务（10 分钟）

**步骤**：
1. 进 `ccguide-练习`，`claude --permission-mode plan` 启动
2. 输入：`@笔记.txt 我想把这份笔记改造成 GTD（Getting Things Done）风格的任务管理——规划一下改造方案，不要改文件`
3. Claude 会给你一个方案（只说不做）
4. 看方案：`/permissions` 切回默认
5. 说"OK，按方案开始"
6. 正常审核 diff

**成功标志**：你体验了"先规划再执行"的流程，并且计划模式下确实没动文件。

### 任务 2：体验 Esc Esc（5 分钟）

**步骤**：
1. 默认模式下，让 Claude 随便改一下 `笔记.txt`（比如"把标题改成大写"）
2. 审核 → Yes → 改完
3. 按两次 Esc（一次、松开、再一次）
4. 看提示：回退成功
5. 切图形界面打开 `笔记.txt` 确认回到了改之前

**成功标志**：Esc Esc 撤销成功，文件回到未改状态。

### 任务 3：用 /rewind 选一个更早的检查点（5 分钟）

**步骤**：
1. 在 Claude Code 里做 3-4 次改动（不用复杂，就是让它改几次文件）
2. 打 `/rewind`
3. 看弹出的检查点列表（应该有 3-4 条）
4. 选一个比"最近一次"更早的检查点（比如第 2 次改动之前的）
5. 确认

**成功标志**：文件状态和对话都回到了你选的那个时刻。

## 如果你卡住了

**症状 A：`/plan` 模式下让它改东西它拒绝了**
- 原因：这是计划模式的预期行为，它就是"不给改"。
- 解决：`/permissions` 切到默认或 acceptEdits 模式

**症状 B：Esc Esc 按了没反应**
- 原因：按太慢（中间间隔太长会被认为是两次独立按键）、或当前没有可回退的操作
- 解决：连续按快一点；或用 `/rewind` 从列表选

**症状 C：`/rewind` 恢复后文件还是错的**
- 原因：那个文件被你**在 Claude Code 外面**（图形界面、其他程序）改过——`/rewind` 不管外面的修改
- 解决：手动恢复，或从 git / 备份拿

**症状 D：`/rewind` 说没有检查点**
- 原因：刚开始对话没几步，还没生成足够多的检查点
- 解决：这个会话暂时没救，用 git / Ctrl+Z / 备份

## 🌿 支线 9.A：把 plan → execute 当默认工作流

> **这段讲什么**：一个值得养成的习惯——几乎所有不那么简单的任务都先 `/plan`。
> **什么时候回头读**：你用了几周、开始做更复杂任务时。

### 我推荐的"默认升级"

早期（前 1-2 周）：大多数任务直接做，踩坑后学习。

中期（2-4 周）：**稍复杂任务（3 步以上、涉及多文件）默认先 `/plan`**：

```
（启动就进 plan 模式）
claude --permission-mode plan

然后：
@目标文件/文件夹 分析一下，告诉我要做 X 该怎么做

看 Claude 方案 → 不满意就让它调整方案 → 满意后：
/permissions → 切回 default
开始做
```

### 好处

- **避免"做一半发现方案错了"的浪费**
- **你有机会中途纠偏**（用嘴改方案比用 diff 改实际文件快 10 倍）
- **复杂任务的"整体感"更强**

### 代价

- 多花 3-5 分钟讨论方案
- 简单任务走这一圈显冗余

> 💡 **判断标准**：任务预计需要 Claude 做 **3 步以上**（多次改文件或跑命令），先 `/plan`。1-2 步的直接做。

## 🌿 支线 9.B：`/rewind` 的边界——它能和不能救什么

> **这段讲什么**：`/rewind` 具体能恢复什么、不能恢复什么。
> **什么时候回头读**：你试图 `/rewind` 但发现没救回来想搞清楚原因。

### `/rewind` 能救的

- ✅ Claude Code 本次会话中**发出的消息**（回退到那个时刻）
- ✅ 本次会话中 **Claude 用 Edit/Write 工具改过的文件**（恢复到检查点的内容）
- ✅ 本次会话中 Claude **新建的文件**（会被删除，回到"未建"状态）

### `/rewind` 救不了的

- ❌ 你**在图形界面 / 其他终端** 改过的文件
- ❌ Claude **通过 `bash` 命令**改过的东西（因为 bash 命令的结果 Claude Code 不知道该怎么回退）——比如它跑了 `rm file.txt`，`/rewind` 不会把文件变回来
- ❌ Claude 安装的软件 / 改的系统设置
- ❌ 已经**被 git commit / push** 的东西（那是 git 的事）
- ❌ **已经关闭会话后**再打开——之前的检查点不一定还在

### 边界清楚了怎么办

**高风险操作的保护策略**：

| 操作类型 | 保护方式 |
|---------|---------|
| Claude 改文件（Edit/Write） | `/rewind` 就能救 |
| Claude 跑 `rm`、`mv` 等命令 | **`/rewind` 救不了** → **操作前手动备份 / git commit** |
| 装软件、改系统设置 | 手动记录可逆的步骤 |
| 远程操作（git push、调 API） | **操作前就要特别小心**——发出去的不一定收得回 |

### 心法

`/rewind` 是**便利工具**而非**终极保险**。重要场景的终极保险永远是：

1. **预防**：`/plan` 模式先规划
2. **备份**：git commit / 手动复制一份
3. **分步小心**：一步一步做、每步验证——而不是一口气 10 步然后指望回退
