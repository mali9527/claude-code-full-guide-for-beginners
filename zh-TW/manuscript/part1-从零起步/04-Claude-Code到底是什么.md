<a id="41-把它理解成能够动手的助手"></a>
## 4.1 把它理解成能夠動手的助手

你已經讓 Claude Code 讀過一份檔案，也稽核過一次改動。現在可以把這個體驗連起來：**它會理解目標，選擇工具，檢視執行結果，再決定下一步**。工具可能是讀取檔案、編輯檔案、執行命令，也可能是經過你配置的外部服務。

<!-- diagram: FIG-006 -->
![你定方向，助手動手](../../../assets/illustrations/FIG-006/revisions/r01/zh-CN.png)

*圖：你給出目標和邊界，助手執行，結果仍由你核對。*
<!-- /diagram: FIG-006 -->

“電腦裡的實習生”仍是一個有用的比喻：它能做事，需要知道你的目標、材料與邊界，完成後也需要檢查。但比喻有邊界。它不真正擁有人的責任感，也不會因為上一輪做對了，就保證下一輪不犯錯。你需要給它可以驗證的完成標準，而不只是“做得好一點”。

例如，“幫我整理資料”很難驗收；“只讀這個練習目錄，把檔案按主題列成一份清單，暫不移動檔案”就清楚得多。你能檢查清單是否遺漏，也能決定下一步是否允許移動。這種小步完成、及時核對的用法，是本書後面所有擴充套件功能的基礎。

另一個容易誤解的地方是“它在我的電腦裡，所以所有處理都在本機”。終端版的檔案工具在本地執行，模型請求通常仍送到你連線的雲端服務。哪些內容送出、如何儲存與訓練，要看具體賬戶和提供方，第 11 章會詳細解釋。

<a id="42-它的能力和权限是两回事"></a>
## 4.2 它的能力和許可權是兩回事

模型越強，通常越擅長規劃和解決困難問題。但**能力不會自動變成許可權**。你選了 Fable 5.1，不代表它獲得管理員許可權；切回較小模型，也不會自動收回之前設定的工具允許規則。

Claude Code 可以幫助你讀寫檔案、整理文字、編寫和執行指令碼、研究產品資料。這些動作是否能夠執行，取決於當前平臺、工具、許可權模式、組織設定以及外部服務是否已連線。它可能需要請求確認，也可能在已有許可或 Auto 模式下直接完成允許的動作。因此，不能把“會彈窗”當作唯一保護，更不能把專案目錄當成鎖住整臺電腦的圍牆。

初學時可以用下面的順序：先讓它讀練習材料並描述發現，再明確要求一次小改動，最後親自開啟結果。檔案較重要，就先留一份可恢復的版本；涉及外部傳送、賬戶或支付，先把物件和範圍說清。普通撤銷無法收回已經送到外部系統的操作。

它也有能力上的限制：回答可能出錯，執行結果需要檢查，當前資訊需要實際查詢。遇到複雜表格或掃描檔案，還可能需要相應工具。讓它誠實說明“看到了什麼、沒讀到什麼、實際做了什麼”，比只看最後一句“完成了”更可靠。

<a id="43-选工具时比较实际工作环境"></a>
## 4.3 選工具時，比較實際工作環境

現在不少聊天產品也能搜尋、分析上傳檔案或使用工具，因此“聊天網站只能打字，Code 才能動手”的舊分法已經不準確。選工具時應先看材料在哪、結果要儲存到哪裡、需要誰來稽核。

| 你眼前的任務 | 可以先考慮的工作方式 |
|---|---|
| 圍繞一段文字討論、修改一份上傳的草稿 | 你已經熟悉的聊天介面 |
| 連續處理本地專案裡的多個檔案，並檢視改動 | Claude Code 終端或桌面 Code |
| 主要處理知識工作材料，偏好圖形介面 | 檢視 Cowork 當前支援的任務與連線方式 |
| 希望任務在遠端執行或跨裝置繼續 | 先了解 Claude Code 的 Web、雲端任務與遠端控制的差異 |

這裡沒有“必須用最複雜工具”的要求。你可以先用熟悉的方式完成小任務，也可以為了獲得更明確的專案和版本管理而學習終端。**本書教的稽核、拆任務、核對來源，對不同介面都有價值。** 具體產品能力以當前官方介紹為準，不把某個版本的介面當作永遠不變的邊界。

<a id="44-到这里决定是否继续深入"></a>
## 4.4 到這裡，決定是否繼續深入

Claude Code 現在有終端、桌面 Code、編輯器整合和 Web 等入口，它們共享不少概念，但功能、配置載入、執行位置和賬戶條件不完全相同。[官方產品概覽](https://code.claude.com/docs/en/overview)

**繼續本書終端主線，需要你已經做到三件事**：知道自己在哪個工作資料夾，知道使用什麼賬號和計費路徑，願意稽核檔案或命令的影響。第 1—3 章就是這三項的補課。如果某一步還不穩，先回去完成練習，不必硬著頭皮裝 Skills 或 MCP。

如果你希望先在圖形介面工作，可以轉到[附錄 H 的桌面導覽](../%E9%99%84%E5%BD%95/H-%E6%A1%8C%E9%9D%A2%E5%BA%94%E7%94%A8%E5%AF%BC%E8%A7%88.md)。桌面應用裡的 Code 與 Cowork 是不同入口：先看所選入口、任務執行位置與許可權說明，再挑合適的工作方式。終端操作的快捷鍵和配置命令不要直接照搬到桌面介面。

如果暫時沒有合適賬戶，或當前工作資料不適合送到雲端，也可以停在這裡，先保留基礎認識。你不需要為了“讀完一本教程”而購買更高套餐。繼續往下時，第 5—10 章會訓練讀檔案、改檔案、命令稽核和驗收；完成這些，再學記憶、模型和擴充套件能力更穩妥。

<a id="45-调整你的预期5-个心智转变"></a>
## 4.5 調整你的預期：5 個心智轉變

很多零基礎使用者用了一兩天 Claude Code 就放棄，通常是**預期沒調整好**。下面 5 個心智轉變必須做——這是本章最值得畫線的一節。

<a id="①-它会犯错审核是你的责任"></a>
### ① 它會犯錯——稽核是你的責任

AI 不是"絕對正確"，它生成的東西**可能有錯**。不要預設日常任務就一定可靠。決定採用結果之前，需要按任務的重要程度核對。

**做法**：養成 **diff 稽核**習慣（第 6 章專講）——改檔案前那個對比圖，**掃一眼**有沒有意外改動。

<a id="②-你永远在开车它只是助手"></a>
### ② 你永遠在開車——它只是助手

它可以建議、可以執行，但**方向盤在你手上**。

**反模式**："Claude 你看著辦" → 它會瞎做；"Claude 這個怎麼樣" → 你讓它替你拿主意。

**正確姿勢**：你想清楚要什麼，告訴它 **WHAT / WHERE / HOW / VERIFY**（第 5 章講這個提問模板），它執行。

<a id="③-描述越具体结果越好"></a>
### ③ 描述越具體，結果越好

模糊的指令：`帮我整理一下笔记`——它會猜你要什麼，很可能猜錯。
具體的指令：`把 ~/Documents/2026会议笔记 里所有 .md 文件按主题分到三个子文件夹：产品 / 运营 / 技术，分类按每个文件头部的标题判断`——目標與分類依據更清楚，也更容易檢查。

<a id="④-它有记忆极限聊太久会变糊涂"></a>
### ④ 它有"記憶極限"——聊太久會變糊塗

Claude Code 每次對話的記憶是有限的（這是**上下文**，第 12 章專講）。一次對話做太多不相關的事、或聊得太長，它會開始犯蠢。

**做法**：先儲存有用的成果和任務狀態，再為不相關的新任務用 `/clear` 開新對話。不要把 10 個不相關的活塞一個對話裡。

<a id="⑤-前两周别指望起飞先建工作流"></a>
### ⑤ 前兩週別指望"起飛"——先建工作流

新手前兩週通常是"先學會安全地用"——稽核、許可權、退出。兩週後你開始**寫 CLAUDE.md**（第 14 章）、裝**第一個 Skill**（第 20 章），工作流才真正成型。

💡 **彆著急**。把實習生培養成骨幹員工，本來就需要時間。

## 本章小結

- Claude Code 是**電腦裡的實習生**，不是聊天機器人、不是自動化機器
- 它可圍繞專案持續使用工具；能力、許可權和執行位置要分別判斷

  1. 它會犯錯，稽核是你的責任
  2. 你永遠在開車，它是助手
  3. 描述越具體，結果越好
  4. 它有記憶極限，聊久會糊塗
  5. 前兩週別指望起飛，先建工作流

### 任務 1：給下一次練習寫清邊界（約 5 分鐘）

從“整理筆記、檢查一份表格、修改一段文字”裡選一件自己的小事。用三句話寫出：材料在哪、允許它做什麼、你怎樣確認做對了。先使用練習副本，不必馬上執行。

**成功標誌**：另一位不知道背景的人，也能看懂任務範圍和完成標準。

<a id="任务-2选定接下来的入口约-3-分钟"></a>
### 任務 2：選定接下來的入口（約 3 分鐘）

確認自己能夠完成第 1—3 章，再決定繼續終端主線、先讀桌面附錄，或暫緩動手。如果要繼續，回到練習目錄核對賬號與模式。

**成功標誌**：你能解釋為什麼選擇這個入口，以及開始前還缺哪項準備。

<a id="-支线-4b什么是-agentic-coding智能体编码"></a>
## 🌿 支線 4.B：什麼是 "agentic coding"（智慧體編碼）

> **這段講什麼**：Claude Code 的這種工作方式有個專門名字，叫 agentic coding。
> **什麼時候回頭讀**：你在別人部落格/影片裡看到這個詞，不知道啥意思。

<a id="传统-ai-聊天-vs-agentic智能体模式"></a>
### 傳統 AI 聊天 vs agentic（智慧體）模式

**單純問答流程**：你問一句，AI 答一段，這輪就結束。是否具有記憶或其他工具能力，應看具體產品。

**Agentic 模式**：AI 是一個**能自主決定行動、反覆迭代直到達成目標**的實體——也就是"智慧體"（agent）。

一個 agentic 系統包括：

1. **目標**（你告訴它要什麼）
2. **感知**（讀環境：檔案、命令輸出、之前的對話）
3. **決策**（思考下一步）
4. **行動**（真的執行：改檔案、跑命令）
5. **觀察結果**（看自己行動之後發生了什麼）
6. **回到 2**，繼續迭代直到任務完成

**Claude Code 就是一個典型的 agentic 工具**。

<a id="agentic-的好处与坑"></a>
### Agentic 的好處與坑

**好處**：
- 一些多步驟任務可從一段目標描述開始；重要任務仍應拆分並設定驗收點
- 能自我糾錯（發現錯了重來）
- 能長時間工作

**坑**：
- 可能"自作主張"做你沒想到的事（所以要稽核！）
- 可能誤入歧途浪費時間（需要你看著點）
- 複雜任務用的 token 多（成本高）

> 💡 **與 agentic 相關的其他工具**：Cursor、Aider、Devin 也都是 agentic 編碼工具，各有特色。Claude Code 的長處是**終端原生 + Anthropic 大模型 + 許可權控制細緻**。
