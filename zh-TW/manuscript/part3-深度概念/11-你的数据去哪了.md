## 11.1 先看一張圖：一次對話的資料去了哪


先沿著最常見的本地終端路徑看一遍。這裡的“本地”是指程式在你的電腦上操作檔案，**不表示模型在你的電腦裡運算**。

<!-- diagram: FIG-013 -->
![一次請求的資料去哪](../../../assets/illustrations/FIG-013/revisions/r01/zh-CN.png)

*圖：傳送的是本次請求所需材料；具體處理與儲存條件按所用服務核對。*
<!-- /diagram: FIG-013 -->

本地程式把輸入、所需檔案內容和工具輸出組織為請求，經 HTTPS 發給實際連線的模型服務；服務返回回覆或下一步操作指令。

還有兩個容易漏掉的方向：會話可能儲存在你電腦上，以便下次繼續；如果啟用雲端會話、遠端控制、外部聯結器或主動傳送反饋，還可能發生相應的資料同步。

<a id="别把文件没上传理解成内容没离开"></a>
### 別把“檔案沒上傳”理解成“內容沒離開”

你給 Claude 一個檔案路徑，它先在本地找到並讀取內容，然後把完成任務所需的資訊提供給模型。檔案的名字和位置沒有變化，不代表其中的文字只待在本地。

命令輸出也是一樣。即使你沒直接貼上金鑰，只要命令把它顯示出來，輸出就可能進入會話。**檢查要交出去的內容，比糾結是複製文字還是引用檔案更有用。**

如果你按附錄 K 接入第三方模型，請把圖裡的服務商換成實際那一家。它的資料政策、所經閘道器與儲存方式需要另查，不能套用 Anthropic 的承諾。

<a id="112-不训练和保存多久是两件事"></a>
## 11.2 “不訓練”和“儲存多久”是兩件事

**訓練**，是在模型改進過程中使用資料；**保留**，是資料仍存放在服務或日誌裡。這兩個問題要分別核對。選擇不用於訓練，不等於請求處理完就立刻消失。

截至 **2026-09-24**，Claude Code 官方資料說明區分了：

| 賬號路徑 | 訓練選擇與通常保留期 |
|---|---|
| Free、Pro、Max 消費者賬號 | 開啟改進模型選項時，可用於訓練並保留 5 年；不開啟時通常保留 30 天 |
| Team、Enterprise、API 商業路徑 | 預設不以程式碼或提示詞訓練生成模型，主動加入資料提供計劃除外；標準保留期通常為 30 天 |
| 獲准的零保留安排 | 需單獨確認資格和協議，普通 Enterprise 套餐不自動等於零保留 |
| 第三方模型或閘道器 | 檢視該服務商及組織的實際約定 |

消費者的開關也會影響**用同一賬號登入的 Claude Code**。到 [Claude 隱私設定](https://claude.ai/settings/data-privacy-controls)核對，而不是認為“我在終端裡，所以個人隱私選項與我無關”。反饋等主動提交材料另有保留規則，詳見[官方資料使用說明](https://code.claude.com/docs/en/data-usage)。

這張表幫助你找到該檢查哪份設定，不是所有場景的合同替代品。工作資料能否輸入，還要看你是否有權交給所選服務處理。面對含有個人資訊或保密內容的檔案，先確定批准範圍，再決定是否脫敏、用假資料演練，或改用符合要求的處理方式。

<a id="113-红线清单这些东西绝对别发给-claude"></a>
## 11.3 紅線清單：這些東西絕對別發給 Claude

先為個人練習畫出邊界：下面這些內容，不直接放進未經批准的個人雲端會話。工作場景有專門授權流程時，按組織的實際規定處理。

<a id="红线-1凭证和密钥"></a>
### 紅線 1：憑證和金鑰

- **API key、token、密碼、證書私鑰**（`~/.ssh/id_rsa`、`.env` 裡的金鑰）
- **資料庫連線字串**（`mysql://user:password@host/db`）
- **OAuth refresh token**、Cookie、JWT
- **加密貨幣私鑰、助記詞**

❌ 不能做：`@.env 帮我加个新字段`——`.env` 裡的金鑰就全傳過去了
✅ 改這樣：把 `.env` 裡的值替換成 `<REDACTED>`，或者單獨把**欄位名**告訴 Claude，不給值

<a id="红线-2他人的个人信息"></a>
### 紅線 2：他人的個人資訊

- **客戶 / 使用者的身份證號、手機號、家庭住址、銀行卡號**
- **身份證、護照、駕照、病歷的掃描件 / 照片**
- **未脫敏的真實員工檔案 / 客戶名單**

❌ 不能做：`@客户名单.xlsx 帮我整理成邮件分组`
✅ 改這樣：先把名單裡的身份證號、手機號替換成 `<ID_1> <ID_2>...`，處理完再手動把原值填回去；或用假資料跑通流程，再自己套真資料

<a id="红线-3公司机密--法律限制"></a>
### 紅線 3：公司機密 + 法律限制

- **商業合同、報價單、未公開的財務報表**
- **核心程式碼**（涉及核心演算法、專利、商業模型）
- **保密協議（NDA）覆蓋的內容**
- **醫療、法律行業涉及個人隱私的檔案**（很多國家有明確法規）

❌ 不能做：直接把合同 PDF 交給 Claude 分析
✅ 改這樣：先問公司 IT / 法務部是否允許；或企業版 + 自建代理；或本地用開源模型

<a id="红线-4会传染的内容"></a>
### 紅線 4：會傳染的內容

有些內容你**以為是你的**，其實別人的權利也摻在裡面：

- 朋友發你的聊天截圖（洩露對方隱私）
- 第三方付費資料（知識付費課件、訂閱制資料）
- 公司下發的內部文件（對你免費，但對 Anthropic 不免費）

**判斷標準**：把內容交給當前連線的服務處理，你是否有權這樣做？檔案的所有者、公司約定與服務設定都需要考慮。

<a id="114-黄线清单要小心的内容可以发但先处理"></a>
## 11.4 黃線清單：要小心的內容（可以發但先處理）

紅線之外，還有一批"不是絕對不行，但要多想一步"的：

<a id="黄线-1自己的隐私信息"></a>
### 黃線 1：自己的隱私資訊

- 自己的身份證號、手機號、地址
- 自己的私人筆記、日記
- 自己的聊天記錄、郵件

**原則**：只提供完成這次任務所需的資訊，先檢查賬號隱私設定。`/clear` 只是開始新對話，不能撤回已經傳送的資料，也不是刪除本地或服務端全部記錄的按鈕。

<a id="黄线-2公司内部可分享的内容"></a>
### 黃線 2：公司內部可分享的內容

- 公開的產品資料、技術部落格草稿
- 內部但非機密的工作流程、會議紀要
- 同事間能隨意轉發的郵件

**原則**：查一下公司 IT 政策。很多公司已經有明確的"AI 使用規範"——允許用 Claude / ChatGPT 處理哪些等級的內容。沒有政策就**問 IT/法務一次**。

<a id="黄线-3代码和项目"></a>
### 黃線 3：程式碼和專案

- 非核心演算法的業務程式碼
- 沒特別機密的配置檔案
- 公開 GitHub 倉庫的內容（這類基本沒問題）

**原則**：公開程式碼通常更容易處理，但仍檢查是否夾帶真實配置、憑證或他人資料。如果是公司閉源商業程式碼——**企業版** / 經組織批准的部署更安全，個人版先問一下。

<a id="115-公司--团队用户的决策清单"></a>
## 11.5 公司 / 團隊使用者的決策清單

如果你是在**公司**裡用 Claude Code，走一遍下面這張清單：

<a id="①-公司有没有-ai-使用政策"></a>
### ① 公司有沒有 AI 使用政策？

- **有**：嚴格按公司政策（可能限制特定目錄、特定資料型別）。
- **沒有**：**先問一次**（IT、法務、合規），別自己判斷。很多踩坑的人是"沒問就用"。


<a id="②-用的是哪条账号和服务路径"></a>
### ② 用的是哪條賬號和服務路徑？

不要只看應用名字。請確認登入的是個人訂閱、團隊席位、API 賬號，還是公司提供的閘道器；再核對它適用的條款、處理範圍與資料位置。

“買了企業版”不能代替這一步。企業功能提供管理選擇，但是否已經啟用、是否覆蓋當前賬號，需要管理員確認。把核對結論記在自己的使用邊界表裡，以後換賬號、換模型服務或換工作電腦時，再複查一次。

<a id="③-哪些任务可以用哪些必须本地处理"></a>
### ③ 哪些任務可以用、哪些必須本地處理？

畫一張**自己的分類表**：

```markdown
# 我的 Claude Code 使用边界

## 可以用（低风险）
- 整理个人笔记、写博客草稿
- 改开源项目代码
- 处理公开资料、翻译公开文档

## 先脱敏再用（中风险）
- 整理含个人数据的表格（先替换关键字段）
- 改公司内部文档（确认非机密后）

## 本地工具代替（高风险）
- 处理合同 / 财报 / 客户名单原始数据
- 改涉密代码
- 处理身份证、医疗档案

## 绝不交给任何云端 AI
- 密钥、密码、数据库凭证
- 未脱敏的身份证 / 银行卡
- NDA 覆盖的文档
```

<a id="本章小结"></a>
## 本章小結

- 程式在本地操作檔案，模型仍可能透過網路接收任務內容。
- 保留和訓練分開看；個人訂閱與商業/API 的約定不同。
- 使用第三方後端時，按實際服務商核對，不沿用另一家的承諾。
- `/clear` 不會撤回資料；金鑰誤發後要作廢重建。
- 先確定檔案可以交給誰處理，再決定直接使用、脫敏或本地處理。

## 動手任務

<a id="任务-1画你自己的使用边界表15-分钟"></a>
### 任務 1：畫你自己的"使用邊界"表（15 分鐘）

**步驟**：

1. 新建 `~/Desktop/ccguide-练习/使用边界.md`
2. 照 11.5 的模板，列出"你自己工作裡的"4 類：可以用 / 先脫敏 / 本地處理 / 絕不上傳
3. 每類至少寫 3 項具體任務

**成功標誌**：看著這張表就能決定"這個任務能不能用 Claude"。

<a id="任务-2查你公司的-ai-政策10-分钟如果在公司用"></a>
### 任務 2：查你公司的 AI 政策（10 分鐘，如果在公司用）

**步驟**：

1. 搜尋公司內網 / 郵件存檔"AI 使用" / "Claude" / "ChatGPT"關鍵詞
2. 如果找不到明確政策，發一封郵件給 IT/合規："我想用 Claude Code 處理 XXX 型別任務，公司是否允許？"
3. 把回覆存成 `公司AI政策.md`

**成功標誌**：你有了明確的"上班可以用 / 不可以用"邊界。

<a id="任务-3脱敏练习10-分钟"></a>
### 任務 3：脫敏練習（10 分鐘）

**步驟**：

1. 自己寫一份虛構通訊錄或配置樣例，使用假姓名、假號碼和 `EXAMPLE_KEY`，不拿真實金鑰做練習
2. 複製一份（別改原件），手動把每個敏感欄位替換成佔位符（`<NAME_1>` `<PHONE_1>` `<KEY_REDACTED>`）
3. 記下你做脫敏的步驟，下次類似檔案複用

**成功標誌**：你掌握了"先脫敏再給 Claude"的基本流程。

<a id="如果你卡住了"></a>
## 如果你卡住了

**症狀 A：我的老闆擔心資料洩露，不讓我用**
- 原因：合理——尤其涉及敏感行業。
- 解決：給老闆看本章 11.1 的資料流圖 + Anthropic 的隱私承諾連結；申請企業版試點；從非敏感任務開始建立信任。

**症狀 B：不知道自己的任務算不算敏感**
- 原因：標準模糊。
- 解決：**預設當作敏感**處理——要麼脫敏再用，要麼問一次。"保守一次"的代價遠小於"洩露一次"。

**症狀 C：不小心把金鑰粘進去了怎麼辦**
- 原因：手滑或忘了檢查。
- 解決：**立刻去那個服務作廢這個金鑰**（GitHub、雲服務、API 平臺都有"revoke"按鈕）；重生一個新的；別依賴"刪除對話"——金鑰已經傳出去了。

<a id="-支线-11a对话记录不只在模型服务里"></a>
## 🌿 支線 11.A：對話記錄不只在模型服務裡

> **這段講什麼**：當你準備共享電腦、傳送反饋或清理資料時，還需要檢查哪些地方。
> **什麼時候回頭讀**：需要向同事解釋資料流，或準備整理舊會話時。

<a id="先检查本地记录"></a>
### 先檢查本地記錄

能繼續昨天的會話，意味著程式需要留下記錄。不要把 Claude Code 的配置和會話目錄，當成一堆可以隨意打包傳送的普通設定檔案。裡面可能含有你曾提供的文字、檔案內容和命令結果。

做電腦備份時，也要意識到這些記錄可能進入備份。清理會話則應按[應用資料說明](https://code.claude.com/docs/en/claude-directory#application-data)檢查實際儲存位置和刪除方法；不懂時先列清單，不讓指令碼直接清空整個配置目錄。

<a id="发送反馈前看范围"></a>
### 傳送反饋前看範圍

報錯時，最有用的是版本、操作步驟、脫敏後的報錯文字。有人請你提供“完整會話日誌”，先檢查它是否包含客戶資料或憑證，再決定提供哪一部分。

在應用裡選擇傳送反饋、分享會話或允許檢視記錄，也應讀清提交範圍。簡單評分和主動附上會話，不一定是同一種資料提交。

<a id="把检查变成一个小习惯"></a>
### 把檢查變成一個小習慣

不用每次發一句普通話都查一遍條款。比較實用的節奏是：首次使用時核對；換賬號、接入新服務、處理另一類資料時複查；公司政策更新時同步邊界表。這樣既能工作，也能清楚自己作了什麼選擇。

<a id="-支线-11b真的不敢上传有没有本地替代"></a>
## 🌿 支線 11.B：真的不敢上傳，有沒有本地替代

> **這段講什麼**：如果你要處理的內容實在敏感，本地跑 AI 有哪些路。
> **什麼時候回頭讀**：確定了有內容不能雲端處理時。


<a id="方案-1经确认的本地工具或模型"></a>
### 方案 1：經確認的本地工具或模型

如果任務是篩選表格、替換文字、統計檔案，普通本地指令碼或表格軟體可能就夠了，不必為每件事啟動一個大模型。

需要本地模型時，可由熟悉配置的人確認模型、所需硬體和聯網設定。**裝在電腦上的應用也可能訪問網路**；是否完全本地，要看實際推理方式、外掛和工具配置。效能與成本也取決於模型和機器，不能用“所有 Mac 都需要某一代晶片”來概括。

最合適的起點，是拿一份不敏感的樣例測試結果，再決定能否滿足你的任務。

<a id="方案-2混合工作流"></a>
### 方案 2：混合工作流

- **敏感部分本地做**：原始資料用本地工具 / 本地模型處理
- **結構化 / 脫敏後交 Claude**：生成模板、做最終潤色

例：合同審閱——原文字地看；只把**條款提綱**（去掉具體數字和名字）交給 Claude 讓它檢查邏輯。


<a id="方案-3经组织批准的云端部署"></a>
### 方案 3：經組織批准的雲端部署

公司可能透過雲平臺或自有閘道器接入 Claude，並集中管理賬號、網路與記錄。它仍可能是雲端服務，**不能因為使用公司賬號或 VPC，就叫作“模型完全在公司內部執行”**。

是否適合某類資料，由公司批准的部署和合同決定。作為普通使用者，確認“我當前連的確實是這條路徑”比記住雲平臺名字更重要。

<a id="一个实用建议"></a>
### 一個實用建議

對**大多數零基礎讀者**來說：

- 日常工作任務（整理檔案、寫文件、翻譯）—— 在你有權處理、賬號設定合適的前提下使用
- 真正涉密的少數場景—— **本地 + 手工** 仍然是最穩的選擇
- 不要因為"聽說 AI 洩露"就全面拒絕，也不要因為"好用"就什麼都上傳

用**分檔策略**（11.4 / 11.5 的表），對不同風險做不同處理。
