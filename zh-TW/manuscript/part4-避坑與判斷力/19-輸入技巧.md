## 19.1 `!` 快跑 shell 命令（已在 Ch 18 提過，這裡說透）

### 用法

提示符處**直接 `!` 開頭**敲命令：

```
!git status
```

效果：Claude Code 跑這個命令，**輸出進上下文**讓 Claude 看到。

### 為什麼值得單獨用

- **提供上下文**："先給 Claude 看 git 狀態再討論怎麼 commit"——比你口述更精準
- **避免中斷流程**：不用切到另一個終端跑了再描述給 Claude

### 常用的 `!` 命令

| 命令 | 幹什麼 |
|-----|-------|
| `!ls` / `!ls -la` | 看當前資料夾 |
| `!pwd` | 看當前在哪 |
| `!git status` / `!git log -n 5` | 看 git 狀態 / 最近 5 次提交 |
| `!cat 檔名` | 把檔案內容貼給 Claude（小檔案可以這樣，大檔案用 @） |
| `!date` | 讓 Claude 知道"今天是幾月幾號" |

### 和 Claude 主動跑命令的區別

- `!command`：**你主動跑**，繞過權限詢問（但仍在 Claude Code 的沙箱裡）
- Claude 要跑命令：它會先說"我要跑 `X`，同意嗎？"—— 走權限彈窗

**用 `!` 的前提**：這個命令你**百分之百確定安全**。

## 19.2 `@` 精準引用——進階用法

基礎用法 Ch 5 講過。**三個進階技巧**：

### 技巧 1：Tab 自動補全

打 `@` 後開始打路徑，**按 Tab**：
- 自動補全檔名
- 如果路徑有多個匹配，再按 Tab 會輪流顯示

**省時**：不用手打長路徑、不會拼錯檔名。

### 技巧 2：引用多個檔案

```
@a.md @b.md 對比這兩份筆記的相同點和差異
```

Claude 會**一次性讀取多個**。

**注意**：`@` 的檔案越多 / 越大，Ctx 消耗越快（見 Ch 12）。**一次 3-5 個是舒適區**。

### 技巧 3：引用檔案的特定段（更精準）

**不要**直接 `@巨型檔案.md`——先自己**定位到關心的區間**：

```
@長文件.md 第 3 節"資料流"那段大概 100-150 行左右，幫我改得更簡潔
```

Claude 會直接定位到那段，不會把幾萬字全讀進來。

（更準一點的話：有些版本支援 `@檔案#錨點` 或 `@檔案:50-80` 語法——查 `/help` 看你的版本是否支援。）

## 19.3 圖片 / 截圖輸入

Claude 能**看圖**——這是很多人不知道的利器。

### 怎麼輸入圖片

**方式 1：直接貼上（最快）**
- 系統截圖（Mac `Cmd+Shift+4`、Windows `Win+Shift+S`）
- **直接 `Cmd+V` / `Ctrl+V`** 貼上到 Claude Code 輸入框
- Claude Code 會顯示 `[image 1]` 之類的佔位
- 發出去，Claude 看到圖

**方式 2：`@` 引用圖片檔案**
```
@~/Desktop/截圖.png 幫我看這張圖裡的錯誤資訊
```

### 什麼場景該用圖

- **報錯截圖**：你看不懂某個報錯視窗——截圖比打字描述準
- **UI 設計稿**：讓 Claude 按稿子寫程式碼
- **表格照片**：把紙上的表格錄進電腦
- **圖表**：讓 Claude 解讀資料圖
- **手寫筆記**：轉成電子版

### 注意事項

- 圖片**也占上下文**（且佔不少）——不要一次塞十張圖
- **不要傳含個人隱私的圖**（身份證、聊天截圖等）——回 Ch 11 複習紅線
- 圖片識別有**誤讀風險**：手寫字 / 模糊文字容易錯——**關鍵資訊自己核對**

### 一個真實場景

```
你：（截圖了一個 Python 報錯）
    這個錯是什麼意思？怎麼修？
Claude：（識別圖裡的 stack trace）
    這是一個 AttributeError，在 line 42 的 ...
    可能原因：...
    修復方案：...
```

**比你打字複述報錯資訊快 10 倍**。

## 19.4 多行輸入——長提示詞的正確姿勢

### 問題

複雜任務需要多行提示詞：

```
我要做 XXX
要求：
1. ...
2. ...
3. ...
限制：...
```

預設按 Enter 就發了——你只能打到第一行就被迫發出。

### 解決

**Shift+Enter**（大部分終端）—— 換行不傳送。

完整流程：

1. 敲第一行
2. **Shift+Enter** 換行
3. 敲第二行
4. **Shift+Enter** 換行
5. ... 都敲完
6. **Enter** 傳送

### 替代方式

某些終端不支援 Shift+Enter，試：
- **Option+Enter**（Mac）
- **Alt+Enter**（Windows / Linux）
- 或使用貼上——在別處寫完多行文字，整體粘進來

### 超長提示詞：用檔案

如果你要發一個**幾百字的複雜提示**，最佳做法：

1. 在文本編輯器裡**把提示詞寫成一個 `.md` 檔案**
2. Claude Code 裡 `@prompt.md`
3. 後面加一句 "按上面這份說明做"

**為什麼這樣更好**：
- 你可以反覆調整 prompt 檔案，不怕每次重敲
- 可以**複用**——下次類似任務直接 `@` 同一個檔案
- 多人協作時能**共享 prompt 模板**

## 19.5 歷史回溯

### 上 / 下鍵翻歷史

在輸入框裡按 **↑**：逐條翻看你之前發過的訊息。

**什麼時候用**：
- 剛才發的那句話想改一下重發——按 ↑ 取回來改
- 翻"幾輪前我具體說了什麼"
- 複用之前的模板化提示

### 搜尋歷史

某些終端支援 **Ctrl+R** 搜尋——打幾個關鍵詞，找到歷史訊息。

**注意**：歷史只在**當次會話內有效**。`/clear` 或退出後清空。

### 貼上失敗時的歷史回溯

一種常見場景：
- 你貼上了一大段文字
- Enter 傳送時發現其中有一處錯
- `/rewind` 回到傳送前
- **按 ↑** 取回那段文字
- 改好後重發

比"從頭寫一遍"快很多。

## 19.6 貼上大段文字的正確姿勢

### 問題

你從網頁 / 文件裡複製一段話，粘進 Claude Code。結果：
- 格式亂了（換行錯位 / 特殊字元）
- 太長，直接爆上下文
- 貼上過程卡頓

### 解決方案

**方案 A：小段（< 10 行）直接粘**
- 正常 Cmd+V / Ctrl+V
- 傳送前檢查一下排版

**方案 B：中段（10-100 行）用多行輸入**
- 先打一句引子："以下是我要討論的段落："
- Shift+Enter 換行
- 貼上
- Enter 傳送

**方案 C：大段（> 100 行 / 很長的文件）儲存為檔案再 `@`**
- 新建 `~/Desktop/待處理.md`
- 把內容儲存進去
- Claude Code 裡 `@~/Desktop/待處理.md`

### 大段文字的兩個陷阱

1. **意外的 Enter**：貼上時某些行結尾是 Enter，可能觸發傳送——**先粘到單獨的文本編輯器整理再二次粘到 Claude Code**
2. **隱藏格式**：從網頁複製的文字可能帶格式標記（HTML），Claude 會讀到"干擾文本"——**粘進 Markdown 檔案先"洗"一遍，再 `@`**

## 動手任務

### 任務 1：把 6 個技巧每個試一次（15 分鐘）

**步驟**：

1. 啟動 Claude Code
2. `!ls` 跑一次 shell 命令
3. `@` + Tab 補全一個檔名
4. 截圖一張圖（任意）貼上給 Claude，問它看到什麼
5. Shift+Enter 發一條三行的訊息
6. ↑ 翻歷史調出剛才的訊息
7. 貼上一段 20 行左右的 Markdown

**成功標誌**：6 個動作都能順利完成——下次無需思考就能用。

### 任務 2：用"檔案 @" 代替長 prompt（15 分鐘）

**步驟**：

1. 想一件你反覆做的任務（如"給我的日報文字潤色"）
2. 把"**完整要求 + 風格說明 + 禁忌**"寫成 `~/Desktop/ccguide-練習/日報潤色-prompt.md`，至少 10 行
3. 下次要做日報潤色時：`@日報潤色-prompt.md @今天的日報.md 按模板走`

**成功標誌**：**你有了第一份可複用 prompt 模板**——以後類似任務一秒啟動。

### 任務 3：截圖流（5 分鐘）

**步驟**：

1. 找一個你看不懂的報錯視窗 / 一張資料圖 / 一張別人的 UI 截圖
2. 截圖粘到 Claude Code 問它解讀
3. 評估回答質量

**成功標誌**：你意識到"**打字描述錯誤**永遠不如截圖給 Claude 看"。

## 如果你卡住了

**症狀 A：Shift+Enter 按下直接傳送了**
- 原因：某些終端僅認 Option+Enter 或 Alt+Enter。
- 解決：都試一下；或用"先寫檔案再 `@`"代替長提示詞輸入。

**症狀 B：貼上圖片沒反應**
- 原因：某些終端不支援圖片貼上。
- 解決：**儲存圖片到本地資料夾再 `@` 路徑**，效果一樣。

**症狀 C：貼上大段文字後 Claude 回覆亂碼 / 看不懂**
- 原因：文字裡有隱藏格式 / 特殊字元。
- 解決：**先粘到 VS Code / 記事本等純文本編輯器**，儲存成 `.md` 檔案，再 `@` 進來。

## 🌿 支線 19.A：鍵盤快捷鍵收藏單

> **這段講什麼**：Claude Code 裡不只 `@`、`!`，還有一堆編輯快捷鍵。
> **什麼時候回頭讀**：你用了一段時間後想提效時。

### 游標移動

| 鍵 | 效果 |
|---|------|
| **Ctrl+A** | 游標跳到行首 |
| **Ctrl+E** | 游標跳到行尾 |
| **Option+←** / **Option+→** | 跳一個詞（Mac） |
| **Alt+←** / **Alt+→** | 跳一個詞（Windows） |

### 刪除

| 鍵 | 效果 |
|---|------|
| **Ctrl+U** | 刪除從游標到行首的內容 |
| **Ctrl+K** | 刪除從游標到行尾 |
| **Option+Delete** | 刪一個詞（Mac） |
| **Ctrl+Backspace** | 刪一個詞（Windows） |

### 會話控制

| 鍵 | 效果 |
|---|------|
| **Ctrl+C** | 中斷當前執行（Claude 思考中按它會停止） |
| **Ctrl+C Ctrl+C**（兩下） | 退出 Claude Code |
| **Esc Esc** | 快速撤銷（見 Ch 9） |

### 把這張表打印出來貼桌面

- 不用背——忘了就翻
- 用多了自然肌肉記憶
- 一週之後基本都會用

## 🌿 支線 19.B：輸入模板庫的搭建

> **這段講什麼**：任務 2 只建了一個模板，展開講如何系統化建"prompt 庫"。
> **什麼時候回頭讀**：你開始在多種任務上反覆用同類提示時。

### 資料夾結構建議

```
~/Desktop/prompts/
├── 寫作/
│   ├── 日報潤色.md
│   ├── 週報生成.md
│   └── 郵件草稿.md
├── 整理/
│   ├── 截圖重新命名.md
│   └── 筆記歸檔.md
├── 程式設計/（如果你會點）
│   ├── 程式碼審查.md
│   └── 寫測試.md
└── README.md   # 一張目錄索引
```

### 每個模板檔案的格式

```markdown
# 任務：日報潤色

## 輸入
我會給你一份原始日報（純流水賬）。

## 輸出要求
- 保留所有真實事項
- 合併相近事項（同一天兩次"改文件"合併）
- 每項 30 字以內
- 順序按重要性，不按時間

## 禁忌
- 不要編造事項
- 不要加 emoji

## 風格示例
- ❌ "今天早上 9 點開會討論了專案進度"
- ✅ "專案會議：Q2 目標確認"
```

### 怎麼用

```
@prompts/寫作/日報潤色.md @今天的日報.md 按模板走
```

### 維護節奏

- **每次做完任務回頭看**：模板能不能更好？更新
- **每月掃一遍**：哪些沒用到的刪掉
- **存進 git**（或雲盤同步）：防止丟失

這一套建立起來之後，**日常任務的提示詞成本降到接近零**——你花 2 分鐘填具體內容，模板把其餘都包了。
