<a id="j1-两个新名字怎样放进你的工作里"></a>
## J.1 兩個新名字，怎樣放進你的工作裡

**Claude Fable 5.1** 於 **2026 年 9 月 1 日**釋出；**Claude Opus 5.5** 於 **9 月 22 日**釋出。兩者都能用於 Claude Code。Fable 面向更難的推理和長時間任務，Opus 5.5 則是現在值得先嚐試的常用模型。這裡沒有“買了更新的就可以不檢查結果”的含義。[Fable 釋出說明](https://www.anthropic.com/claude-fable-and-mythos-5-1)、[Opus 釋出說明](https://www.anthropic.com/claude-opus-5-5)

先想一個與你有關的例子：你有三份活動方案，需要找出預算和日期上的衝突，整理出一份可以執行的安排。可以先用 Opus 5.5，把材料和完成標準給全。如果它遺漏了關鍵約束，先指出遺漏，確認是不是檔案沒讀到、要求沒說清。只有當問題確實在複雜判斷上，才值得試更高投入或 Fable。

Fable 並不意味著“小任務也必須交給它”。它的標準 API 輸入/輸出單價是每百萬 token **10/50 美元**；Opus 5.5 是 **4/20 美元**。token 是模型處理內容的單位，不是固定字數。兩者模型視窗都是 **1M token**，最大輸出 **128K token**；視窗是可處理空間，不是免費贈送額度。[Fable 規格](https://platform.claude.com/docs/en/models/fable-5-1/overview)、[Opus 規格](https://platform.claude.com/docs/en/models/opus-5-5/overview)

對用訂閱的人，最先核對的仍是“這個模型消耗哪份額度”，而不是拿 API 單價計算月費。相關套餐差別和查賬方法已放在[第 15 章](../part3-%E6%B7%B1%E5%BA%A6%E6%A6%82%E5%BF%B5/15-%E6%A8%A1%E5%9E%8B%E4%B8%8E%E6%88%90%E6%9C%AC.md)。

<a id="j2-升级软件以后再确认完整模型名"></a>
## J.2 升級軟體以後，再確認完整模型名

先退出正在輸入的 Claude Code 對話，回到普通終端。Mac 的終端和 Windows 的 PowerShell 都可以輸入：

<!-- diagram: FIG-040 -->
![升級後怎樣確認自己在用什麼](../../../assets/illustrations/FIG-040/revisions/r01/zh-CN.png)

*圖：先核對當前版本、可用模型與賬戶資格，再決定使用方式。*
<!-- /diagram: FIG-040 -->

```sh
claude --version
```

`--version` 表示顯示版本號。如果低於 **2.1.280**，先按[第 2 章的安裝與更新方法](../part1-%E4%BB%8E%E9%9B%B6%E8%B5%B7%E6%AD%A5/02-%E5%AE%89%E8%A3%85-Claude-Code.md)升級。原生安裝通常用 `claude update`；透過軟體包管理器安裝的，按原來的安裝方式更新。本篇統一用 2.1.280 作為最低操作基線，是為了同時覆蓋兩款新模型。

回到工作資料夾後，可以在普通終端啟動一場明確指定模型的會話：

```sh
claude --model claude-opus-5-5
```

這條命令中的 `--model` 表示“本次啟動使用後面的模型”。如果已進入會話，就用 `/model` 開啟選擇器；希望長期改用這個版本，可以輸入 `/model claude-opus-5-5`。不要把普通終端命令與會話裡的斜槓命令輸反。[命令列引數參考](https://code.claude.com/docs/en/cli-reference)

下面是**用於讀懂選項的文字示意，不是實測截圖，實際排序和可選項以你的介面為準**：

```text
当前模型：看完整名称和版本
需要试用：在 /model 中选中模型，按 s，仅用于本次会话
准备长期使用：按 Enter 保存，或输入 /model 完整模型名
出现 Requires usage credits：先确认额外用量，再决定是否继续
```

在當前官方直連環境中，`opus` 通常指 Opus 5.5，`fable` 指 Fable 5.1；公司的閘道器——統一轉發模型請求的服務——可能另有對映。已儲存的模型、恢復的舊會話及組織設定，也可能影響啟動結果。**升級程式後看一眼實際模型名**，比只憑一個“Opus”簡寫放心。確切選擇、會話與預設設定的關係見[模型配置說明](https://code.claude.com/docs/en/model-config)。

<a id="j3-effort-是投入档位不是回答长短开关"></a>
## J.3 effort 是投入檔位，不是回答長短開關

舊版教程曾建議 Opus 4.7 保留 `xhigh`。現在換到 Opus 5.5，不能把這一條機械照搬。**Opus 5.5 預設 `medium`；Fable 5.1 預設 `high`。** 模型之間的同名檔位並不是統一刻度，`medium` 也不等於“只能做中等難度的事情”。

可以在 Claude Code 會話裡輸入 `/effort` 開啟選擇，或者輸入 `/effort medium` 明確選擇 medium。常見五檔為 `low`、`medium`、`high`、`xhigh`、`max`，表示逐步提高思考投入。檔位會影響時間和消耗，但不是每升一檔都穩定提升結果。新手先用模型預設值，拿真正會遇到的任務比較，再決定是否調整。[effort 官方說明](https://platform.claude.com/docs/en/build-with-claude/effort)

舉個練習場景：整理一頁記錄時，medium 已經把負責人和日期列對了。把檔位調高後，仍是同樣三項結果，只是等得更久，就沒有必要為這件事長期使用高檔。處理幾份相互衝突的方案時，若提高投入後多找出了一個關鍵矛盾，這個調整才有具體價值。

Opus 5.5 和 Fable 的思考機制始終開啟，舊教程中的“關閉思考讓它馬上回答”不能照搬；相關開關鍵對它們不起關閉作用。想要簡短答案，應直接要求“用三句話解釋”，而不是把降低 effort 當成字數限制。[當前互動快捷鍵說明](https://code.claude.com/docs/en/interactive-mode)

也不必為了升級，把所有舊提示詞重寫一遍。先保持任務不變，比較模型預設表現；如果慢得不合適，再調整投入。如果答案不對，回到依據和檢查標準，而不是一口氣拉到 `max`。

<a id="j4-新模型更能持续工作你要把做到哪里算完说清楚"></a>
## J.4 新模型更能持續工作，你要把“做到哪裡算完”說清楚

長任務的關鍵，是讓 Claude 知道最終交付什麼、允許碰哪些材料、怎樣判斷完成。你不必把每一箇中間步驟都替它安排好，也不要只給一句“幫我把這些都搞定”，讓它猜你真正需要什麼。

下面是**本書設計的練習輸入，不是已完成任務的實測記錄**：

> **你**：請比較工作資料夾裡的三份活動方案，產出一份“待決定事項.md”。先找日期、人數、預算口徑不一致的地方，再給出可供我選擇的修改建議。每個問題標明來自哪份材料；沒有依據的數字不要補。保留三份原稿，不聯絡任何人，也不代我預訂。完成後檢查：三份材料是否都覆蓋、金額是否沿用原單位、每個建議是否有依據。過程中發現影響結論的新情況，請簡短告訴我；完成時列出仍需我決定的事項。

這裡的檔名只是示例，你應換成自己的實際材料。這個任務已經允許讀取、比較和生成結果，但沒有授權對外發訊息或預訂。**換用更強模型，不等於把任務邊界擴大。** Claude Code 的許可權規則也獨立於模型選擇；提示詞說明意圖，許可權設定決定哪些操作能執行。[許可權說明](https://code.claude.com/docs/en/permissions)

新模型的長任務表現值得嘗試，但你仍要看“完成了什麼”。如果它說“下一步我將核對金額”，隨後結束了回答，而檔案裡還留著未經核對的數字，那就是任務未完成。可以指出具體剩餘項，讓它繼續完成；連續嘗試沒有進展時，先查缺少什麼資訊。

官方也提醒，長任務可能出現中途結束、進度不足或未經要求的擴充套件。對入門使用，實用做法是把範圍和完成條件寫明，並在拿到結果後抽查來源，而不是把“模型會自檢”當作人的檢查已經多餘。[Opus 5.5 用法建議](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5)、[Fable 5.1 用法建議](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1)

<a id="j5-看懂加速和换模型别凭感觉判断故障"></a>
## J.5 看懂“加速”和“換模型”，別憑感覺判斷故障

舊版書曾把 `/fast` 寫成某個舊模型專屬的入口。現在 **Opus 5.5 支援快速模式**，訂閱使用者使用它會走額外付費用量。它仍是 Opus 5.5，並沒有因為響應更快而變成另一款“簡化模型”。要不要用，應看你是否需要縮短等待，以及是否接受相應費用；第一次學會讀檔案、改文件時，不需要為練習開啟加速。[快速模式說明](https://code.claude.com/docs/en/fast-mode)

另一類變化是**回退**：原本選擇的模型在某個請求上沒有繼續處理，系統把請求交給另一個模型。回退與 fast 是兩回事。Fable 5.1 和 Opus 5.5 在部分安全檢查觸發時會出現這種情況，介面會說明切換。Opus 5.5 的某些網路安全請求可能轉給 Opus 4.8，某些生物領域請求可能轉給 Opus 5。[模型切換說明](https://support.claude.com/en/articles/16049681-why-claude-switched-models-in-your-conversation-with-opus-5-or-opus-5-5)

因此，發現版本變了，先看訊息記錄和當前選擇，不必馬上斷定訂閱失效。你最初選中了 Fable，也不能據此保證這次對話的所有回答都出自 Fable。若模型在正常工作中錯誤拒絕，可以記錄提示並透過官方反饋入口報告；不要把不斷改寫請求去“躲過檢查”當成教程技巧。

反過來，模型顯示正確也不保證任務已經完成。新模型的回答更短、措辭更順，或者彙報得更有條理，都只是交流表現。你的判斷仍落在檔案是否正確、依據是否可靠、修改是否符合要求上。把這一條留住，後續模型再更新，你也有穩定的檢查方法。

<a id="本章小结"></a>
## 本章小結

- Fable 5.1 與 Opus 5.5 都已釋出，本篇基線是 Claude Code 2.1.280 或更新版本。
- 升級後確認完整模型名；舊會話和儲存的設定可能仍使用舊選擇。
- Opus 5.5 預設 medium，Fable 5.1 預設 high，不用一律開最高檔。
- Fable 是否包含在套餐裡，要按賬戶和席位核對。
- fast 是付費加速，回退是模型變化，1M 則是空間上限。
- 把長任務的目標、邊界和完成條件講清楚，再檢查實際結果。

<a id="动手任务"></a>
## 動手任務

<a id="任务-1确认一次升级结果约-5-分钟"></a>
### 任務 1：確認一次升級結果（約 5 分鐘）

1. 在普通終端輸入 `claude --version`，記錄版本；低於 2.1.280 時按第 2 章更新。
2. 啟動 Claude Code，開啟 `/model`，記錄完整模型名及是否顯示額外收費提示。
3. 開啟 `/effort`，記錄當前檔位；再用 `/usage` 檢視賬戶用量。無需更換模型或購買額度。

**成功標誌**：你能清楚寫下“軟體版本、模型版本、思考檔位、付款方式”四項，且不把它們混為一談。

<a id="任务-2让它完成一个可核验的小任务约-10-分钟"></a>
### 任務 2：讓它完成一個可核驗的小任務（約 10 分鐘）

1. 準備兩段自己寫的活動安排，故意放入一個日期衝突。不要用真實客戶資料。
2. 參考 J.4，要求它找衝突、標來源並生成一份建議，明確保留原文。
3. 手動核對它是否找出衝突，有沒有擅自補數字。如果沒有完成，把漏掉的項明確指出。

**成功標誌**：你拿到一份能對照原文檢查的結果。完成這項任務不要求 Fable，也不要求 fast；使用當前可用的模型即可。

<a id="如果你卡住了"></a>
## 如果你卡住了

**問題 A：已經更新，還是沒有 Fable 5.1 或 Opus 5.5。** 看清軟體版本、賬戶可用範圍和組織限制。公司閘道器也可能沒有接入完整模型名；保留錯誤提示，問管理員確認對映，不要反覆改成猜測的名字。

**問題 B：選 Fable 後提示額外用量。** 這可能符合套餐規則。Pro 的 Fable 從開始使用就另行付費；不想增加支出，可以取消並繼續使用已包含的模型。詳見[第 15 章](../part3-%E6%B7%B1%E5%BA%A6%E6%A6%82%E5%BF%B5/15-%E6%A8%A1%E5%9E%8B%E4%B8%8E%E6%88%90%E6%9C%AC.md)。

**問題 C：模型變慢，或任務結束得太早。** 先檢視 effort 和是否真的完成；高檔位可能增加等待。任務未完成時指出剩餘交付物；如果缺材料，補材料。不要把反覆發“繼續”當成唯一排查辦法。

<a id="-支线-ja保留有用的提示词把旧版本口诀放下"></a>
## 🌿 支線 J.A：保留有用的提示詞，把舊版本口訣放下

**這段講什麼、什麼時候讀**：你存了一套幾個月前的提示詞，升級後想判斷哪些該改時，回來讀。

“說明目標、提供依據、寫出驗收條件”仍然有效，因為它們表達的是你的任務。容易過時的是依賴某一代模型特點的口訣：永遠預設 Sonnet、Opus 一定最貴、必須設 xhigh、任務一結束就清空、思考過程越長越可信。不要把這些句子原封不動留在每次都會讀到的專案規則裡。

可以做一個小整理：先挑你最常用的三條提示詞，保留任務與限制，去掉沒有明確用途的重複要求。用同一份材料試一下，檢查質量有沒有下降。只要結果確實變差，就把需要的約束補回來；不必為了追求“新模型不需要提醒”，刪除仍然幫助你的說明。

Fable 5.1 的官方指南專門提到，低投入時可能減少檢索，長任務可能少報進度，也可能做出超出原請求的擴充套件。你可以針對觀察到的問題補一句具體要求，例如“涉及最新價格請查官方來源”，或“只修改指定檔案”。這比把整篇提示詞模板複製進專案更容易維護。[Fable 5.1 提示指南](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1)

對 Opus 5.5，同樣先評估預設檔位，不必繼承以前的最大投入；需要可見進度時說清什麼時候希望聽到彙報。提示詞的作用是幫助它完成你的任務，不是保證一個固定咒語能長期適用於所有模型。

<a id="-支线-jb同一个别名为什么同事打开的是另一个版本"></a>
## 🌿 支線 J.B：同一個別名，為什麼同事開啟的是另一個版本

**這段講什麼、什麼時候讀**：你和同事都輸入 `/model opus`，顯示卻不同，或者在第三方雲上無法選中新模型時，再看這一節。

模型**別名**是便於輸入的短名字。服務把短名字對應到哪個完整版本，會受到 Claude Code 版本、服務提供方和組織配置影響。例如，本篇核對時官方直連的 `opus` 已指向 Opus 5.5，而一些第三方環境仍可能指向舊版。`fable` 在 Claude apps gateway 會話中也可能仍指向 Fable 5。完整名稱能減少歧義，但不能讓供應商突然獲得一個沒有部署的模型。

因此，排查時最好一次給管理員四項資訊：Claude Code 版本、連線的服務、你輸入的名稱、介面返回的錯誤。不要把真實金鑰貼進截圖。管理員確認支援的新版本和名稱後，你再按他提供的配置操作。[不同提供方的模型配置](https://code.claude.com/docs/en/model-config)

如果你是在自己寫程式，透過 API 連線模型，那又是另一層遷移。Fable 5.1 和 Opus 5.5 有涉及思考內容、工具選擇與響應格式的相容性變化，不能只把程式裡的模型名稱替換掉就認定完成。本篇面向使用 Claude Code 的人，不要求你改這些引數；程式開發者應另讀[Fable 規格與遷移入口](https://platform.claude.com/docs/en/models/fable-5-1/overview)和[Opus 規格與遷移入口](https://platform.claude.com/docs/en/models/opus-5-5/overview)。
