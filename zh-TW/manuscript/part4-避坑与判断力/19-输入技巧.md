## 19.1 `!` 快跑 shell 命令（已在 Ch 18 提過，這裡說透）

<a id="用法"></a>
### 用法

提示符處**直接 `!` 開頭**敲命令：

```
!git status
```

效果：Claude Code 直接執行你寫出的命令，**把命令和輸出加入會話**。當前預設還會讓 Claude 對結果作出回應，因此也可能產生模型用量。不要把 `!` 理解為“免費呼叫模型的捷徑”。

<a id="为什么值得单独用"></a>
### 為什麼值得單獨用

- **提供上下文**："先給 Claude 看 git 狀態再討論怎麼 commit"——比你口述更精準
- **避免中斷流程**：不用切到另一個終端跑了再描述給 Claude

<a id="常用的--命令"></a>
### 常用的 `!` 命令

下面按常見 shell 寫法示意。Windows 使用 PowerShell 時，可用 `Get-ChildItem -Force` 代替 `ls -la`；先看當前使用的 shell。Git 相關命令還要求你已安裝 Git，並進入 Git 專案。

| 命令 | 幹什麼 |
|-----|-------|
| `!ls` / `!ls -la` | 看當前資料夾 |
| `!pwd` | 看當前在哪 |
| `!git status` / `!git log -n 5` | 看 git 狀態 / 最近 5 次提交 |
| `!cat 文件名` | 把檔案內容貼給 Claude（小檔案可以這樣，大檔案用 @） |
| `!date` | 讓 Claude 知道"今天是幾月幾號" |

<a id="和-claude-主动跑命令的区别"></a>
### 和 Claude 主動跑命令的區別

`!command` 表示你直接指定了要執行的命令，不需要 Claude 先理解目標再選擇命令。**它通常在 Claude Code 沙箱之外執行**，即使你已為模型呼叫啟用沙箱；官方列出的嚴格沙箱會話是例外。你仍受作業系統等外層許可權限制，但不能因為視窗裡寫著 Claude Code，就把它當成隔離環境。

模型自己呼叫工具時，則按當前許可權模式與規則處理：可能詢問，也可能按預先許可或 Auto 模式執行。兩種入口都需要你看懂目標路徑、影響範圍與輸出。先從 `!pwd`、`!git status` 這樣的檢查開始，輸出裡也不要夾帶金鑰。

命令輸出預設會觸發 Claude 的回應，這部分和普通提問一樣消耗用量。`respondToBashCommands: false` 可以改成只把輸出加入上下文；之後繼續對話時，這些材料仍可能作為輸入處理。完整行為見[官方互動模式](https://code.claude.com/docs/en/interactive-mode)。

<a id="192--精准引用进阶用法"></a>
## 19.2 `@` 精準引用——進階用法

基礎用法 Ch 5 講過。**三個進階技巧**：

<a id="技巧-1用候选列表补全"></a>
### 技巧 1：用候選列表補全

打 `@` 後開始輸入路徑，候選列表會幫你找到檔案。用方向鍵選中正確項，再按 Tab 或 Enter 接受；傳送前檢查輸入框裡的路徑，最後按 Enter 傳送。不要把“補全候選”和“提交整條訊息”混成同一步。

目錄相近時，先輸入更多路徑字元再選，比反覆猜檔名更穩。自動補全也不能替你判斷同名檔案是不是這次要處理的那一份。

<a id="技巧-2引用多个文件"></a>
### 技巧 2：引用多個檔案

```
@a.md @b.md 对比这两份笔记的相同点和差异
```

多個檔案會作為本輪材料提供給 Claude；傳送前確認它們都與任務相關。

**注意**：`@` 引用會佔用上下文（見 Ch 12）。幾份短筆記與幾份巨型日誌不能只按“檔案個數”比較；先挑與任務有關的材料。

<a id="技巧-3只想讨论局部时先控制材料范围"></a>
### 技巧 3：只想討論區域性時，先控制材料範圍

`@长文档.md` 會把檔案內容加入會話。後面再寫“只看第 100—150 行”，是告訴模型關注哪裡，**並不保證前面沒有加入全文**。[官方檔案引用說明](https://code.claude.com/docs/en/common-workflows#reference-files-and-directories)

若只需要一個小段落，可以先複製該段正文，註明來源和必要背景；或者先不使用 `@`，這樣描述：

```
请只读取当前目录“长文档.md”的第 100—150 行，
解释其中“数据流”一节的含义。先不要修改文件。
如果缺少上下文，告诉我还需要哪一段。
```

這給出了區域性讀取的要求；實際讀取了什麼，仍應檢視工具記錄。不要依賴未經當前版本驗證的 `@文件#锚点` 或 `@文件:行号` 寫法。要修改原文時，再讓它核對目標位置與相關上下文，避免只憑一段摘錄誤改檔案。

<a id="193-图片--截图输入"></a>
## 19.3 圖片 / 截圖輸入

Claude 能**看圖**——這是很多人不知道的利器。

<a id="怎么输入图片"></a>
### 怎麼輸入圖片

**方式 1：把圖片放進剪貼簿，再貼上**

- **Mac**：需要直接複製選區截圖時，按 Control+Command+Shift+4，再框選區域；單獨 Command+Shift+4 通常儲存為圖片檔案，不會自動把圖片放進剪貼簿。也可先開啟已有圖片並複製。
- **Windows**：用 Win+Shift+S 框選截圖，使影象進入剪貼簿。
- 回到 Claude Code 輸入框，通常用 **Ctrl+V** 貼上圖片；iTerm2 也支援 Cmd+V，Windows / WSL 可用 Alt+V。終端可能攔截按鍵，以當前[官方按鍵表](https://code.claude.com/docs/en/interactive-mode)為準。
- 先確認出現 `[Image #1]` 一類圖片標記，再補充你希望分析的問題，按 Enter 傳送。只有文字或檔案路徑出現時，不要假定影象已經貼入。

Mac 的截圖行為見 [Apple 截圖說明](https://support.apple.com/en-us/102646)。

**方式 2：給出圖片檔案路徑**

貼上不成功就把圖片儲存到練習目錄，用 `@` 選中它，或直接給出完整路徑：

```
请查看当前练习目录中的“截图.png”，
解释红框里的错误信息；先不要修改任何文件。
```

檔名只是示例，請換成你實際儲存的那一份。傳送前確認檔案存在，並檢視 Claude 是否確實讀到了圖片。[官方圖片工作流](https://code.claude.com/docs/en/common-workflows#work-with-images)


<a id="什么场景该用图"></a>
### 什麼場景該用圖

- **報錯截圖**：展示報錯視窗與位置；有可複製的錯誤原文時，把文字一併提供
- **UI 設計稿**：讓 Claude 按稿子寫程式碼
- **表格照片**：把紙上的表格錄進電腦
- **圖表**：讓 Claude 解讀資料圖
- **手寫筆記**：轉成電子版

<a id="注意事项"></a>
### 注意事項

- 圖片**也占上下文**（且佔不少）——不要一次塞十張圖
- 圖片可能包含姓名、賬戶、金鑰或客戶材料；只提供本次任務需要且允許處理的部分，傳送前檢查。資料邊界見 Ch 11
- 圖片識別有**誤讀風險**：手寫字 / 模糊文字容易錯——**關鍵資訊自己核對**

<a id="一个教学示意"></a>
### 一個教學示意

```
你：（截图了一个 Python 报错）
    这个错是什么意思？怎么修？
Claude：（识别图里的 stack trace）
    这是一个 AttributeError，在 line 42 的 ...
    可能原因：...
    修复方案：...
```

這個對話只是示意，實際錯誤和解釋以自己的材料為準。若有可複製的報錯原文，優先提供文字；影象更適合說明視窗位置、圖表和排版。

<a id="194-多行输入长提示词的正确姿势"></a>
## 19.4 多行輸入——長提示詞的正確姿勢

<a id="问题"></a>
### 問題

複雜任務需要多行提示詞：

```
我要做 XXX
要求：
1. ...
2. ...
3. ...
限制：...
```

預設按 Enter 就發了——你只能打到第一行就被迫發出。

<a id="解决"></a>
### 解決

**Shift+Enter** 在支援該組合鍵的終端裡換行，不傳送。若沒有生效，用 `/terminal-setup` 檢視當前終端支援情況，或採用下方替代方式。

完整流程：

1. 敲第一行
2. **Shift+Enter** 換行
3. 敲第二行
4. **Shift+Enter** 換行
5. ... 都敲完
6. **Enter** 傳送

<a id="替代方式"></a>
### 替代方式

若 Shift+Enter 沒生效，**Ctrl+J** 是官方提供的通用換行方式；也可以輸入 `\` 後按 Enter。Mac 的 Option+Enter 需要終端把 Option 配成 Meta。先用無關緊要的三行練習一下，再傳送長任務。

你也可以在文字編輯器中寫完提示，整體複製過來。無論採用哪種方式，都在傳送前看一遍輸入框，確認它仍是一條完整訊息。

<a id="超长提示词用文件"></a>
### 超長提示詞：用檔案

如果你要發一個**幾百字的複雜提示**，最佳做法：

1. 在文字編輯器裡**把提示詞寫成一個 `.md` 檔案**
2. Claude Code 裡 `@prompt.md`
3. 後面加一句 "按上面這份說明做"

**為什麼這樣更好**：
- 你可以反覆調整 prompt 檔案，不怕每次重敲
- 可以**複用**——下次類似任務直接 `@` 同一個檔案
- 多人協作時能**共享 prompt 模板**

<a id="195-历史回溯"></a>
## 19.5 歷史回溯

<a id="上--下键翻历史"></a>
### 上 / 下鍵翻歷史

在輸入框裡按 **↑**：逐條翻看你之前發過的訊息。

**什麼時候用**：
- 剛才發的那句話想改一下重發——按 ↑ 取回來改
- 翻"幾輪前我具體說了什麼"
- 複用之前的模板化提示

<a id="搜索历史"></a>
### 搜尋歷史

在 Claude Code 輸入區按 **Ctrl+R** 搜尋已輸入的提示詞。當前全屏介面可切換本會話、本專案與所有專案的範圍；經典介面的搜尋範圍和接受按鍵不同。先看當前提示，通常先把匹配項放回輸入框修改，不要急著重複提交。

輸入歷史與當前會話上下文是兩回事。`/clear` 開新會話後，舊會話和本地輸入歷史仍可能保留；它不是刪除隱私記錄的命令。記錄管理見第 11 章。

<a id="发出去才发现文字有错"></a>
### 發出去才發現文字有錯

如果 Claude 還在工作，先按 Esc 或 Ctrl+C 中斷，核對它已經做了什麼。若只是補充條件，可以直接發糾正內容；需要回到之前的對話節點時，再開啟 `/rewind`，選對話恢復或其他確實需要的動作。

恢復對話後，原提示通常會回到輸入框，可在這裡修改重發。檔案恢復是另一個選項，命令和外部系統的副作用也不會因為重發提示自動消失。這一點與第 9 章一致。

## 19.6 貼上大段文字的正確姿勢


<!-- diagram: FIG-022 -->
![長材料先整理，再輸入](../../../assets/illustrations/FIG-022/revisions/r01/zh-CN.png)

*圖：短任務直接表達，長材料放檔案並引用；目錄樹和命令保持可複製。*
<!-- /diagram: FIG-022 -->

<a id="问题-1"></a>
### 問題

你從網頁 / 文件裡複製一段話，粘進 Claude Code。結果：
- 格式亂了（換行錯位 / 特殊字元）
- 材料太多，佔掉任務需要的上下文
- 貼上過程卡頓

<a id="解决方案"></a>
### 解決方案

**方案 A：小段（< 10 行）直接粘**
- 正常 Cmd+V / Ctrl+V
- 傳送前檢查一下排版

**方案 B：中段（例如 10—100 行）先寫引子，再檢查貼上內容**

- 先寫“以下是我要討論的段落”，用已驗證可用的換行鍵換行。
- 貼上正文；較長內容可能摺疊成貼上標記，這是介面收起了文字，不代表省下了 token。
- 確認內容與問題都完整，再按 Enter。

**方案 C：很長或需要複用的材料，儲存為檔案**

把資料儲存為練習目錄裡的 `待处理.md`，再決定是引用全文，還是按 19.2 只提供相關片段。儲存成檔案方便管理版本和複用，**本身不會降低全文被加入會話後的上下文用量**。上面的行數只是整理習慣，不能替代檢視實際材料大小。

<a id="发送前最后看两处"></a>
### 傳送前最後看兩處

第一，看貼上的正文是否完整。有些終端會將大段文字摺疊顯示；不確定時先在本地文字編輯器核對，不要連續重貼、重複傳送。第二，看複製內容裡是否帶入不相關的網頁導航、賬戶資訊或金鑰。儲存為 Markdown 不會自動刪除這些內容，需要你自己檢查。

<a id="本章小结"></a>
## 本章小結

- `!command` 快跑 shell 命令（你確定安全時），輸出給 Claude 當上下文
- `@` 三進階：**候選補全 / 多檔案 / 控制材料範圍**；引用全文後追加行號不等於區域性讀取
- **圖片 / 截圖**先放入剪貼簿，再用適合終端的圖片貼上鍵；有可複製的報錯文字就直接給文字
- **多行輸入用已驗證可用的 Shift+Enter 或 Ctrl+J**；長提示可存檔案複用
- **↑/↓ 翻歷史**；大段貼上的三檔方案（< 10 / 10-100 / 100+）

<a id="动手任务"></a>
## 動手任務

<a id="任务-1把-6-个技巧每个试一次15-分钟"></a>
### 任務 1：把 6 個技巧每個試一次（15 分鐘）

**步驟**：

1. 啟動 Claude Code
2. `!ls` 跑一次 shell 命令
3. 輸入 `@`，選擇候選並按 Tab 補全一個檔名
4. 截一張不含敏感資訊的練習圖，按 19.3 放入剪貼簿並貼上，確認圖片標記後再提問
5. 用 Shift+Enter 或 Ctrl+J 寫三行，最後按 Enter 發出一條訊息
6. ↑ 翻歷史調出剛才的訊息
7. 貼上一段 20 行左右的 Markdown

**成功標誌**：6 個動作都能順利完成——下次無需思考就能用。

<a id="任务-2用文件--代替长-prompt15-分钟"></a>
### 任務 2：用"檔案 @" 代替長 prompt（15 分鐘）

**步驟**：

1. 想一件你反覆做的任務（如"給我的日報文字潤色"）
2. 在實際使用的練習目錄中建立 `日报润色-prompt.md`，寫下完整要求、風格說明和禁忌；行數不限，以清楚為準
3. 在該練習目錄啟動 Claude Code，並準備 `今天的日报.md`；輸入 `@日报润色-prompt.md @今天的日报.md 按模板走`

**成功標誌**：你有了第一份可複用 prompt 模板，並能在正確目錄呼叫它。

<a id="任务-3截图流5-分钟"></a>
### 任務 3：截圖流（5 分鐘）

**步驟**：

1. 找一個你看不懂的報錯視窗 / 一張資料圖 / 一張別人的 UI 截圖
2. 截圖粘到 Claude Code 問它解讀
3. 評估回答質量

**成功標誌**：你確認 Claude 實際讀到了圖片，並能判斷這次用圖還是用報錯原文更清楚。

<a id="如果你卡住了"></a>
## 如果你卡住了

**症狀 A：Shift+Enter 按下直接傳送了**
- 原因：終端沒有按預期傳遞這個組合鍵。
- 解決：改用 Ctrl+J，或先寫檔案；按 /terminal-setup 與官方終端說明配置後，再用練習文字驗證。

**症狀 B：貼上圖片沒反應**
- 原因：剪貼簿裡可能不是影象，或終端攔截了按鍵。
- 解決：先確認剪貼簿內容並按 19.3 選擇按鍵；仍不成功就儲存圖片並提供準確路徑，核對實際讀取結果。

**症狀 C：貼上大段文字後 Claude 回覆亂碼 / 看不懂**
- 原因：文字裡有隱藏格式 / 特殊字元。
- 解決：**先粘到 VS Code / 記事本等純文字編輯器**，儲存成 `.md` 檔案，再 `@` 進來。

<a id="光标移动"></a>

| 鍵 | 效果 |
|---|------|

| 鍵 | 效果 |

## 🌿 支線 19.B：輸入模板庫的搭建

> **這段講什麼**：任務 2 只建了一個模板，展開講如何系統化建"prompt 庫"。
> **什麼時候回頭讀**：你開始在多種任務上反覆用同類提示時。

<a id="文件夹结构建议"></a>
### 資料夾結構建議

```
~/Desktop/prompts/
├── 写作/
│   ├── 日报润色.md
│   ├── 周报生成.md
│   └── 邮件草稿.md
├── 整理/
│   ├── 截图重命名.md
│   └── 笔记归档.md
├── 编程/（如果你会点）
│   ├── 代码审查.md
│   └── 写测试.md
└── README.md   # 一张目录索引
```

<a id="每个模板文件的格式"></a>
### 每個模板檔案的格式

```markdown
# 任务：日报润色

## 输入
我会给你一份原始日报（纯流水账）。

## 输出要求
- 保留所有真实事项
- 合并相近事项（同一天两次"改文档"合并）
- 每项 30 字以内
- 顺序按重要性，不按时间

## 禁忌
- 不要编造事项
- 不要加 emoji

## 风格示例
- ❌ "今天早上 9 点开会讨论了项目进度"
- ✅ "项目会议：Q2 目标确认"
```

<a id="怎么用"></a>
### 怎麼用

```
@~/Desktop/prompts/写作/日报润色.md @今天的日报.md 按模板走
```

上面的模板路徑沿用 Mac 示例。Windows 請換成你實際建立的模板檔案路徑，並確保日報位於當前工作目錄；路徑補全可幫助你選對檔案。

<a id="维护节奏"></a>
### 維護節奏

- **每次做完任務回頭看**：模板能不能更好？更新
- **每月掃一遍**：哪些沒用到的刪掉
- **存進 git**（或雲盤同步）：防止丟失

模板可以減少重複編寫要求的時間，但不會消除模型呼叫費用。每次仍需檢查模板是否適合眼前任務，再填入具體材料。
