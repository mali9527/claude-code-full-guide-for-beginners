# 第 5 章：讓它讀檔案

> **本章在全書的位置**：第二部分 · 第 5 章 / 預估閱讀+動手時長：**主線 30-40 分鐘 + 支線 10-15 分鐘**
>
> **前置章節**：第 3 章（會啟動和對話）
>
> **學完能做什麼（主線）**：能用 `@` 引用讓 Claude 精準讀到你想讓它看的檔案、會用"WHAT/WHERE/HOW/VERIFY"模板提出清晰指令、讓它看懂截圖和多檔案。

- **你會遇到什麼問題**：你讓 Claude 做事，它做出來的不是你要的——十有八九是**你沒讓它"看到"你真正想讓它處理的東西**。

- **讀完你會多會什麼事**：能精準讓它讀指定檔案、用結構化模板問清楚需求、讓它看圖片和截圖。

<a id="51-让-claude-看到内容的三种方式"></a>
## 5.1 讓 Claude "看到"內容的三種方式

要 Claude 處理什麼，它得先"看到"。有三種方式：

| 方式 | 怎麼用 | 適合什麼場景 |
|------|-------|-----------|
| **① `@` 引用** | 輸入框打 `@文件名` | 處理特定檔案——**首選** |
| **② 直接貼上** | Ctrl+V / Cmd+V 把內容貼進對話 | 短文字片段、從瀏覽器複製的一段話 |
| **③ 讓它自己找** | "看看當前資料夾裡有啥" | 你不確定要處理哪個檔案，讓它先探查 |

📌 **最重要的是掌握方式 ①**——它是 Claude Code 和 ChatGPT 的最大差異之一。

<a id="52--引用的具体用法"></a>
## 5.2 `@` 引用的具體用法

`@` 是 Claude Code 的"**精確指路**"符號。在輸入框裡打 `@`，會彈出一個**自動補全選單**列出當前資料夾裡的檔案，用方向鍵選或者繼續打字過濾。

<!-- diagram: FIG-007 -->
![把正確的材料交給它](../../../assets/illustrations/FIG-007/revisions/r01/zh-CN.png)

*圖：先選擇相關材料，再交代要解決的具體問題。*
<!-- /diagram: FIG-007 -->

<a id="单文件"></a>
### 單檔案

```
@笔记.txt 总结一下这份内容
```

Claude 會先讀 `笔记.txt`，再按你要求總結。

<a id="子文件夹里的文件"></a>
### 子資料夾裡的檔案

```
@Documents/周报.md 帮我改一下这份周报的语气
```

路徑可以帶子目錄。

<a id="一个文件夹让它看这里所有文件"></a>
### 一個資料夾（讓它看這裡所有檔案）

```
@会议纪要/ 里面每份笔记分别抓一个关键点
```

`@文件夹名/` 末尾帶斜槓，Claude 會把這個資料夾裡的檔案都掃一遍。

> ⚠️ **大資料夾慎用**：如果裡面有幾十上百個檔案，一次掃完**會消耗大量上下文**（下一章概念"上下文"詳講）。精準到具體檔案比"掃一個資料夾"更好。

<a id="多个文件一起引"></a>
### 多個檔案一起引

```
@第一章.md @第二章.md 把这两章合并成一份摘要
```

連續打幾個 `@` 沒問題。

<a id="图片mac-和-windows-都行"></a>
### 圖片（Mac 和 Windows 都行）

```
@设计稿.png 看这张图，帮我把布局描述成文字
```

Claude 能"看"截圖、設計稿、流程圖。這是個**很被低估**的能力。

💡 **讓它看當前資料夾結構而不讀具體內容** → 見 🌿 支線 5.A。

<a id="53-提问的what--where--how--verify模板"></a>
## 5.3 提問的"WHAT / WHERE / HOW / VERIFY"模板

新手最常見的毛病：**問得太籠統**。看兩個例子：

<a id="模糊版-"></a>
### 模糊版 ❌

```
你：@周报.md 帮我改一下这份周报
```

Claude 會猜：你想改語氣？改錯別字？加內容？刪內容？——猜中算你走運，猜偏你得反覆糾正。

<a id="清晰版-"></a>
### 清晰版 ✅

```
你：@周报.md 
- WHAT: 把这份周报的语气从"严肃正式"改成"轻松简洁"
- WHERE: 只改正文部分，不动标题和日期
- HOW: 长句拆短；去掉"兹此"、"特此"之类的官话
- VERIFY: 改完后字数不超过 500 字，看起来像朋友之间汇报进度
```

Claude 一次就能做對。

<a id="模板解释"></a>
### 模板解釋

| 欄位 | 含義 | 作用 |
|-----|------|-----|
| **WHAT** | 要幹什麼 | 定義目標 |
| **WHERE** | 改哪裡 / 限制範圍 | 防止它亂動 |
| **HOW** | 具體做法、風格 | 統一審美 |
| **VERIFY** | 怎麼驗證做對了 | 給出可檢查的成果標準 |

> 💡 **不一定每次都要寫這四項**——簡單任務一句話就行（"把檔名裡的空格換成下劃線"）。但**任務越複雜，越要用這個模板**。

<a id="54-为什么具体永远比模糊好"></a>
## 5.4 為什麼"具體"永遠比"模糊"好

再看兩組對比：

<a id="整理文件"></a>
### 整理檔案

**模糊**：`帮我整理一下下载文件夹`
**具體**：`@Downloads/ 把里面的 PDF 按文件名里的年份分到 2024/、2025/、2026/ 三个子文件夹；没有年份的放到"待分类/"`

<a id="写东西"></a>
### 寫東西

**模糊**：`帮我写个文案`
**具體**：`写一段 80 字朋友圈文案，宣传明天下午 3 点的免费书法公开课。风格亲切、口语化，带一个 call-to-action（比如"扫码预约"），不要用表情符号`

<a id="调代码"></a>
### 調程式碼

**模糊**：`帮我看看这代码哪里不对`
**具體**：`@app.py 运行到第 42 行 toggle_dark_mode 函数时报 AttributeError。帮我定位原因，给修改建议，但先不改——我要先看方案`

**規律**：
- **加數字**（80 字、3 點）
- **加位置**（第 42 行、哪個資料夾）
- **加風格約束**（親切、不要表情）
- **加驗收標準**（帶 CTA、不要改動，先看方案）

每多一個具體限制，Claude 輸出的"中籤率"就高一截。

<a id="55-让它看图片截图是你的好朋友"></a>
## 5.5 讓它看圖片：截圖是你的好朋友

Claude 能**看懂圖片**——截圖、設計稿、手繪流程圖、表格截圖、錯誤介面……這個能力特別適合：

- **貼個錯誤彈窗截圖**：`@error.png 这个报错是什么意思？怎么解决？`
- **貼個設計稿讓它生成文字描述**：`@mockup.png 这个登录页要什么元素？给我列出来`
- **貼張手繪思維導圖**：`@脑图.jpg 帮我把这张图整理成结构化大纲`
- **貼 Excel 截圖讓它分析**：`@sales.png 这张销售表里哪个季度最好？`

<a id="怎么把截图放进去"></a>
### 怎麼把截圖放進去

**方式 A（推薦，最快）**：在對話裡**直接貼上**——截圖（Mac `Cmd+Shift+4` / Windows `Win+Shift+S`）截好後直接 `Cmd+V` / `Ctrl+V`，Claude Code 會把圖片貼進對話。

**方式 B**：把圖片檔案儲存到工作資料夾，然後 `@图片名.png` 引用。

**方式 C**：拖拽圖片檔案到 Claude Code 的終端視窗（某些終端支援）。

> 💡 **對零基礎使用者特別有用**：很多場景"用文字描述好累"——**截個圖最快**。比如遇到奇怪的報錯、想讓它幫看看 Excel 某一列、想參考某個設計稿……

<a id="本章小结"></a>
## 本章小結

- `@` 引用是**讓 Claude 精準看到內容**的最重要方式（單檔案、資料夾、圖片都能引）
- **WHAT / WHERE / HOW / VERIFY** 四字提問模板——任務越複雜越要用
- **具體**永遠比"模糊"好：加數字、加位置、加風格、加驗收
- 圖片截圖直接貼上進對話，Claude 能看懂——很多場景比文字描述快 10 倍

<a id="动手任务"></a>
## 動手任務

<a id="任务-1用--引用读并总结5-分钟"></a>
### 任務 1：用 @ 引用讀並總結（5 分鐘）

**步驟**：
1. 進 `ccguide-练习` 資料夾，`claude` 啟動
2. 輸入 `@笔记.txt 用 3 条要点概括这份内容`，回車
3. 看結果

**成功標誌**：Claude 輸出的 3 條要點和檔案內容對得上。

<a id="任务-2用-whatwherehowverify-改一份文件10-分钟"></a>
### 任務 2：用 WHAT/WHERE/HOW/VERIFY 改一份檔案（10 分鐘）

**步驟**：
1. 桌面建一個新檔案 `草稿.md`，貼上任意一段你寫過的文字（週報、郵件、總結，200 字以上）
2. 把它複製到 `~/Desktop/ccguide-练习/` 裡
3. Claude Code 裡輸入：
   ```
   @草稿.md
   - WHAT: 改进这段文字的可读性
   - WHERE: 只改正文，标题和签名不动
   - HOW: 长句拆短、去重复、关键词加粗
   - VERIFY: 改完看起来像适合手机阅读的简洁版
   ```
4. 稽核 diff，選 Yes 或 No

**成功標誌**：Claude 改出來的版本確實更好讀，你基本認可。

<a id="任务-3让它看截图5-分钟"></a>
### 任務 3：讓它看截圖（5 分鐘）

**步驟**：
1. 截一張你電腦桌面的圖（Mac `Cmd+Shift+4` / Windows `Win+Shift+S`）
2. 切到 Claude Code 輸入框
3. 貼上（`Cmd+V` / `Ctrl+V`）
4. 問："**這張圖裡有什麼內容？**"

**成功標誌**：Claude 能說出截圖裡有的東西（應用、資料夾、大概幾個圖示等）。

<a id="如果你卡住了"></a>
## 如果你卡住了

**症狀 A：打 `@` 沒有彈出檔案列表**
- 原因：你不在一個有檔案的資料夾，或那個資料夾裡檔案太多被限制了。
- 解決：`Ctrl+C` 兩次退出 → `cd` 到目標資料夾 → 重新 `claude`

**症狀 B：Claude 說找不到你引用的檔案**
- 原因：檔名打錯、副檔名少了（`.txt` 和 `.md` 區分）、或檔案不在當前資料夾裡
- 解決：退出 → `ls` 看資料夾裡的準確名字 → 重新引

**症狀 C：貼上截圖沒反應**
- 原因：極少數老終端不支援。
- 解決：把截圖儲存成檔案（`Cmd+Shift+4`/`Win+Shift+S` 後選儲存到桌面），再 `@截图名.png` 引用

<a id="-支线-5a让-claude-浏览整个文件夹不读内容只看结构"></a>
## 🌿 支線 5.A：讓 Claude 瀏覽整個資料夾（不讀內容只看結構）

> **這段講什麼**：你不確定要處理哪個檔案，想讓 Claude 先"掃一眼"整個資料夾的結構（不讀內容）。
> **什麼時候回頭讀**：你要讓 Claude 處理一堆檔案，但不想讓它一次把內容全讀進來（上下文爆炸）。

<a id="场景"></a>
### 場景

你有個資料夾 `~/Documents/工作` 下面 30 多個 Word 和 PDF，想讓 Claude 先告訴你每份檔案大概是啥主題，再決定讓它處理哪幾個。

<a id="做法"></a>
### 做法

```
帮我列出 ~/Documents/工作/ 里所有文件的文件名和大小，不要读内容。
```

Claude 會跑一個命令（比如 `ls -la`）列出來，不讀檔案內容，節省上下文。

然後你根據列表挑：

```
@季度报告Q1.pdf @季度报告Q2.pdf 把这两份的要点放到一张对比表里
```

> 💡 **原則**：**先瀏覽，再精讀**——尤其資料夾裡東西多時，這樣能省大量上下文。

---

<a id="-支线-5b让-claude-读网页--url"></a>
## 🌿 支線 5.B：讓 Claude 讀網頁 / URL

> **這段講什麼**：Claude Code 能讀網址裡的內容（在你允許的情況下）。
> **什麼時候回頭讀**：你想讓 Claude 參考一篇部落格、查一個文件、看一個產品頁。

<a id="方式-a直接贴-url"></a>
### 方式 A：直接貼 URL

```
读一下 https://example.com/xxx 这篇博客，帮我总结 5 个要点
```

Claude 會問你是否允許它上網，你選 Yes 它就會用內建工具去取內容。

<a id="方式-b你自己用浏览器复制粘贴"></a>
### 方式 B：你自己用瀏覽器複製貼上

簡單粗暴但可靠——瀏覽器裡全選複製，貼到對話裡。適合：
- 頁面需要登入才能看
- 頁面有很多 JS 渲染（Claude 可能取不全）
- 你只想要某一段

<a id="注意"></a>
### 注意

- **URL 取內容會消耗較多 token**（算在成本/上下文裡）
- **敏感資訊不要用 URL 方式**（會把 URL 傳到雲端）
- **區域網或需認證的網頁**通常 Claude 取不到——用方式 B
