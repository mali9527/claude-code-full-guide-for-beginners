<a id="71-让它跑命令是什么意思"></a>
## 7.1 "讓它跑命令"是什麼意思

前面幾章 Claude 在乾的都是**讀檔案、改檔案**。但它還有一個更強的能力：**在你電腦上跑命令**。

"跑命令"就是讓終端執行一條指令——你在第 1 章學過的 `ls` / `cd` 是命令；裝軟體的 `npm install` 是命令；重新命名檔案的 `mv`、刪東西的 `rm`、下載的 `curl`、git 操作、跑 Python 指令碼……**全都是命令**。

<a id="典型场景"></a>
### 典型場景

- "把 ~/Downloads 裡所有 PDF 重新命名，前面加今天的日期" → Claude 會跑 `mv` 迴圈
- "統計這 30 個 Excel 裡'已付款'多少條" → 跑 Python 指令碼
- "壓縮這張大圖到 500KB 以下" → 跑 `sips` 或 `imagemagick`
- "把這個專案裡的依賴都更新一下" → 跑 `npm update`
- "看看這個程序在佔資源嗎" → 跑 `ps` / `top`

**這是 Claude Code 作為本地工作助手的核心能力之一**——但因為命令能真改動你電腦，**必須有許可權機制**。

<a id="72-权限机制先学三种再认识自动模式"></a>
## 7.2 許可權機制：先學三種，再認識自動模式


先把“你想交給它多少自主權”想清楚，再選模式。初學時，本書建議你**主動選擇 Manual（手動確認）**。配置名仍是 `default`，這個單詞不保證它就是你賬號的啟動預設值：當前 Pro、Max、Team 的部分終端/編輯器會話會從 Auto 開始，組織設定、模型和版本也會影響結果。

<!-- diagram: FIG-009 -->
![先看動作，再看授權](../../../assets/illustrations/FIG-009/revisions/r02/zh-CN.png)

*圖：判斷一次操作，要一起看動作、作用範圍與當前許可權規則。*
<!-- /diagram: FIG-009 -->

| 模式 | 配置名 | 它怎樣工作 | 本書建議 |
|---|---|---|---|
| **手動確認 Manual** | `default` | 讀取與部分只讀命令可直接執行，需要授權的操作停下來問 | 用來熟悉許可權和稽核流程 |
| **自動接受編輯** | `acceptEdits` | 自動透過工作範圍內的檔案編輯及部分檔案系統命令 | 任務範圍清楚、已有備份時再用 |
| **計劃 Plan** | `plan` | 探查、執行探索命令、寫方案，通常不改原始檔 | 先把方案想清楚 |
| **自動 Auto** | `auto` | 用後臺判斷機制審查操作，減少逐次確認 | 能稽核最終結果之後再嘗試 |

注意，**Plan 不等於電腦完全只讀**：它需要讀取資料，也可能執行獲准的命令。沒有啟用繞過許可權時，原始檔編輯會被限制到批准計劃之後。Auto 也不保證每個動作都正確。把模式看成協作方式，別把它看成備份的替代品。[官方模式說明](https://code.claude.com/docs/en/permission-modes)



<a id="两个容易看错的名字"></a>
### 兩個容易看錯的名字

`dontAsk` 的含義是“遇到原本需要問你的操作就拒絕”，已經允許的動作和無需審批的讀取仍能繼續。它通常用於自動化，不是“全部答應”，也不是一個名叫 allowList 的模式。**allow、ask、deny 是許可權規則**，與模式分開管理。

`bypassPermissions` 會跳過大部分許可權檢查。本書練習不啟用它；尤其不要把“啟用繞過許可權”當成 Plan 的配套步驟。某些互動式會話只要允許進入繞過模式，計劃期間的編輯限制也會改變。[許可權規則與模式](https://code.claude.com/docs/en/permissions)

<a id="怎么切换"></a>
### 怎麼切換

**啟動時明確選擇**，比猜賬號預設值可靠：

```
claude --permission-mode default
```

這條命令讓本次練習從 Manual 開始。要先做計劃，改用：

```
claude --permission-mode plan
```

**會話中按 Shift+Tab**，觀察輸入區附近的模式文字，切到你需要的一項再停。不要背“按兩次一定是什麼模式”：可用模式會隨配置變化。`/permissions` 用來檢視和修改許可權規則，不能替代核對當前模式。

還有一種看起來像切模式的動作：許可權框中的“以後不再詢問”。它可能儲存某條命令或網站的規則，也可能只允許本會話的檔案編輯。**看完整選項，確認它影響多久、允許多大範圍**，不能一概理解成“只在這次對話有效”。

<a id="新手的三原则"></a>
### 新手的三原則

1. 在專用練習目錄裡，從 Manual 開始認識它會做什麼。
2. 範圍不清楚的任務先規劃，想清楚改哪些檔案、怎樣驗收。
3. 少點幾次確認的前提，是你已經能判斷後果並儲存好原件。

<a id="73-怎么读权限弹窗"></a>
## 7.3 怎麼讀許可權彈窗

下面是許可權詢問的教學示意。第一次遇到不認識的命令，可以停下來慢慢讀，不必趕在幾秒內作決定：

```
Claude wants to run:

    rm -rf ~/Downloads/*.zip

This will remove all .zip files in ~/Downloads.

❯ Allow once
  Yes, and do not ask again
  Deny and tell Claude what to do differently
```

<a id="按顺序核对不必抢着确认"></a>
### 按順序核對，不必搶著確認

**Step 1：看命令本身**——最關鍵那一行是什麼？
- `rm` = 刪
- `mv` = 移動 / 重新命名
- `cp` = 複製
- `curl` / `wget` = 下載
- `sudo ...` = 用管理員許可權（**高度警惕**）
- `npm install` / `pip install` = 裝 Node.js / Python 包
- `git commit` / `git push` = 提交程式碼 / 推送程式碼

**Step 2：看命令作用範圍**——動的是你預期的檔案/位置嗎？
- `~/Downloads/*.zip` = 只動下載資料夾裡的 zip ✅ 預期
- `~/*` 或 `/*` = 整個家目錄/整個磁碟 ⚠️ 危險
- `.`（當前資料夾）= 當前位置；先用 `pwd` 核對，當前位置也可能包含重要資料

**Step 3：看描述**——Claude Code 通常會在命令下一行**用自然語言解釋這條命令在做什麼**，沒看懂命令就讀描述。

<a id="三个选项怎么选"></a>
### 三個選項怎麼選

| 選項 | 含義 | 什麼時候 |
|------|-----|---------|
| **Allow once** | 允許一次，下次類似命令還會問 | 命令你看懂了、沒問題 |
| **以後不再詢問** | 按選項顯示的範圍儲存批准，部分規則跨會話生效 | 你看懂了完整規則且確實需要重複使用 |
| **Deny** | 不允許 + 讓 Claude 換個方法 | 看不懂、或這不是你想要的命令範圍 |

**新手心法**：沒必要長期批准時，先允許一次。並非每個許可權框都有相同的選項。

<a id="74-四类高风险命令必须识别"></a>
## 7.4 四類高風險命令——必須識別

有些命令**一旦跑錯幾乎救不回來**，必須學會一眼識別。

<a id="危险类-1删除类"></a>
### 危險類 1：刪除類

```
rm -rf 路径       # 强制递归删除（删文件夹和里面所有东西）
rm 文件           # 删单个文件
del 文件          # Windows 删
```

⚠️ **關鍵字**：`rm`、`del`、`-rf`（強制遞迴）

**看到就要思考**：**刪的範圍對嗎？刪錯了能恢復嗎？**

<a id="危险类-2覆盖类"></a>
### 危險類 2：覆蓋類

```
mv A B            # 目标 B 是已有文件时，可能覆盖；B 是目录时含义不同
cp A B            # 目标 B 是已有文件时，也可能覆盖
> 文件            # 把内容写到文件，会覆盖原内容
```

⚠️ **關鍵字**：`>` 單箭頭（覆蓋） vs `>>` 雙箭頭（追加）

<a id="危险类-3提权类"></a>
### 危險類 3：提權類

```
sudo ...          # 用管理员权限跑（Mac）
```

Windows 的“以管理員身份執行”是介面操作，不是一條名叫 `Run as Admin` 的命令。

⚠️ `sudo` 開頭的任何命令都要**高度警惕**——影響範圍可能是整個作業系統。

<a id="危险类-4下载--执行"></a>
### 危險類 4：下載 + 執行

```
curl https://xxx.com/script.sh | bash
wget xxx | sh
```

⚠️ 這種模式：**從網上下一段指令碼直接執行**。風險極高——你不知道指令碼里寫了什麼。

**做法**：先確認下載地址、來源和用途。第 2 章的官方安裝命令也採用下載指令碼的方式；應從官方安裝頁取得完整命令，不把陌生帖子裡的地址當作同一回事。看不懂的指令碼，先讓 Claude 解釋，再決定是否執行。

<a id="一个不完全清单安全感参考"></a>
### 一個不完全清單（安全感參考）

| 命令 | 大致安全度 | 說明 |
|------|----------|-----|
| `ls` / `pwd` / `cat` / `head` / `tail` | ✅ 只讀 | 看東西，不改 |
| `mkdir` / `touch` | 🟡 寫入 | 前者建目錄；後者新建空檔案或更新已有檔案的時間戳 |
| `cd` | ✅ 切換 | 只改"當前位置" |
| `cp 到新位置` | 🟡 一般安全 | 複製通常無害，但目標存在會覆蓋 |
| `mv` 到新位置 | 🟡 一般 | 移動，覆蓋風險 |
| `git add` / `git commit` | 🟡 版本控制 | 儲存暫存內容；檢查是否誤含秘密，提交鉤子也可能執行程式 |
| `rm` / `del` | ⚠️ 高風險 | 永久刪除 |
| `sudo` 開頭 | ⚠️ 高風險 | 提權 |
| `curl xxx \| bash` | 🔴 極高風險 | 從網下載執行 |


<a id="75-权限设置在哪改"></a>
## 7.5 許可權設定在哪改

輸入 `/permissions`，先看已經存在的規則及其來源。可能是你以前批准過的，也可能來自專案或組織。發現“為什麼這次沒問我”，先查這裡，再檢查當前模式。

個人設定常在 `~/.claude/settings.json`，專案共有設定在 `.claude/settings.json`，專案個人設定在 `.claude/settings.local.json`。介面會顯示規則來自哪個檔案；初學時不用手寫一大段配置。修改規則前，先說明想允許的**具體操作和目錄**，讓 Claude 展示改動供你核對。

許多普通的 `ls`、`pwd`、`git status` 操作本來就屬於無需詢問的讀取。它們直接執行不代表許可權系統壞了，也不需要為了跟教程一樣彈框而把所有讀取都攔住。

許可權規則也不是檔案隔離牆。它們決定某個工具呼叫能否透過；**沙箱**則限制命令執行後能接觸哪些檔案和網路。再加上檔案備份與結果檢查，才是一套完整的保護。初學時先把操作放在練習目錄內；需要更嚴格隔離時，再閱讀[沙箱說明](https://code.claude.com/docs/en/sandboxing)。

<a id="本章小结"></a>
## 本章小結

- Claude Code 的“跑命令”能力會實際影響電腦和外部服務，但**必須透過許可權系統**
- **新手主動選擇 Manual**，再逐步理解 acceptEdits、Plan 和 Auto 的差別
- **永遠不要用** `--dangerously-skip-permissions` / `bypassPermissions`
- 讀許可權彈窗：**命令 → 範圍 → 描述**，不懂就先查清
- **四類高風險命令**：刪除（`rm`）/ 覆蓋（`>`）/ 提權（`sudo`）/ 下載執行（`curl | bash`）
- 新手心法：能只允許一次，就先只允許一次；儲存規則前讀清作用範圍

<a id="动手任务"></a>
## 動手任務


<a id="任务-1辨认没弹窗与需要批准5-分钟"></a>
### 任務 1：辨認“沒彈窗”與“需要批准”（5 分鐘）

**步驟**：

1. 進入 `ccguide-练习` 資料夾，用 `claude --permission-mode default` 啟動。
2. 請它列出當前檔案。讀取可能直接完成，留意顯示的工具與結果。
3. 請它“使用檔案編輯工具，新建一份 `权限练习.txt`，內容寫‘僅供練習’”。
4. 如果出現許可權框，核對檔案位置後只允許一次；如果直接完成，檢視當前模式和 `/permissions` 裡的現有規則。
5. 開啟新檔案，確認結果。

**成功標誌**：你能說明這次操作為什麼需要或不需要批准，而不只是等到一個固定的彈窗。

<a id="任务-2先看整理方案10-分钟"></a>
### 任務 2：先看整理方案（10 分鐘）

1. 用 `claude --permission-mode plan` 開啟練習會話。
2. 輸入：“請給這個練習資料夾提出整理方案，不移動、不刪除檔案。”
3. 檢查方案裡的範圍是否僅限練習目錄。
4. 需要執行時，在計劃批准選項中選擇手動稽核編輯，或按 Shift+Tab 切到 Manual 再發出指令。

**成功標誌**：你能把“討論方案”與“批准執行”分成兩個步驟。

<a id="任务-3在临时文件上练习拒绝5-分钟"></a>
### 任務 3：在臨時檔案上練習拒絕（5 分鐘）

1. 保持 Manual，讓 Claude 用檔案編輯工具把 `权限练习.txt` 改成另一句文字。
2. 如果出現詢問，選拒絕，並解釋：“先給我看建議文字，暫時不要改檔案。”
3. 若已有長期批准導致沒有詢問，先用 `/permissions` 檢查並撤銷該練習規則，再試一次。
4. 開啟檔案確認它的實際內容。

**成功標誌**：你會拒絕一次操作並說明新的邊界。本練習不使用你的下載目錄或真實重要檔案。

<a id="如果你卡住了"></a>
## 如果你卡住了

**症狀 A：許可權彈窗太頻繁，每點幾下就彈一次**
- 原因：當前操作沒有匹配到已有批准，或規則明確要求詢問。
- 解決：
  - 只在範圍確實合適時儲存窄規則，先讀清選項會持續多久。
  - 用 `/permissions` 檢查已儲存的規則；結束會話不保證持久規則自動消失。

**症狀 B：命令看不懂，不知道選 Yes 還是 No**
- 原因：命令太長或不熟悉。
- 解決：選 **Deny**，告訴 Claude："**用自然語言描述一下你想做什麼**"；它說人話解釋後你再決定

**症狀 C：不小心 Yes 了危險命令**
- 原因：手快或沒看清。
- 解決：
  - **立即 Esc** 停止當前生成；正在執行的命令也要檢查是否已停止。停止不能逆轉已經發生的改動
  - 中斷後立刻檢查：被改動的檔案是否還在、git 能否回滾、備份能否恢復
  - 下次刻意放慢節奏

<a id="-支线-7a什么时候值得用自动接受模式acceptedits"></a>
## 🌿 支線 7.A：什麼時候值得用自動接受模式（acceptEdits）

> **這段講什麼**：`acceptEdits` 許可權模式的合理使用場景——不是越早開越好，但確實有合適的時機。
> **什麼時候回頭讀**：用熟了一兩週、開始覺得反覆點 Yes 很煩、能識別風險了。

<a id="开启方式"></a>
### 開啟方式

啟動時：`claude --permission-mode acceptEdits`
會話中切換：按 Shift+Tab，看到 accept edits 後停下。


<a id="它做什么不做什么"></a>
### 它做什麼、不做什麼

自動接受編輯會讓檔案編輯和範圍內的部分檔案系統命令直接執行，**不能簡單記成“只放行 Edit，所有命令仍然問”**。讀取和原有允許規則也照常生效；受保護位置等操作仍可能被攔下。

這就像從“每改一句都讓你簽字”，換成“按約定改完一小段再交你稽核”。因此你要提前說明哪些檔案可動，完成後自己檢查差異。沒彈窗，只代表這條授權路徑允許執行，不代表改得正確。

<a id="适合的场景"></a>
### 適合的場景

- **重構 / 批次改文件**——你已經給了清晰指令，Claude 會改幾十處，都是預期內的
- **明確範圍的迭代**——"把這個檔案裡所有 'foo' 改成 'bar'"這類
- **你已經儲存了目標檔案的舊版本**——先確認 Git 或備份實際覆蓋它們

<a id="不适合的场景"></a>
### 不適合的場景

- ❌ **第一次用 Claude Code**——你不熟悉它的行為
- ❌ **重要專案第一次碰**——風險過高
- ❌ **你累了 / 分心了**——稽核能力下降

**切回 Manual 的時機**：換到不熟悉的任務前，重新核對模式。恢復舊會話時也檢查一次，不要假設重開視窗就回到手動確認。

<a id="-支线-7b建一个私人白名单"></a>
## 🌿 支線 7.B：建一個私人白名單

> **這段講什麼**：把常用的只讀命令加進"以後不問"的白名單，減少打斷。
> **什麼時候回頭讀**：你已經用了至少 1-2 周、識別命令風險有了直覺。


<a id="思路"></a>
### 思路

先檢查哪些重複詢問真的影響你，再新增最窄的一條規則。只讀命令常常已能直接執行，無需抄一份長白名單。

例如，團隊有一個你已經看懂的檢查命令，可以從“允許這條完整命令”開始。不要為了省一次確認，就把所有 `git`、所有 `python` 或所有網路命令一併允許：同一個程式可以查詢，也可以寫檔案和釋出內容。

<a id="怎么改"></a>
### 怎麼改

先讓 Claude **解釋擬議規則，不寫入**，例如：

```
我反复运行同一条检查命令。请说明当前为什么询问、
最窄可以允许到什么范围，以及规则准备保存在哪个文件。
先展示修改，不要直接写入。
```

確認含義後，再透過 `/permissions` 或已稽核的配置改動儲存。若規則引入了萬用字元，讓它舉出“會被放行”和“仍需詢問”的具體例子。儲存之後只用無害命令試驗，別拿刪除真實資料來測試是否會攔住。

<a id="写在最后"></a>
### 寫在最後

**白名單省事但要剋制**——哪怕每天少 20 次確認，一年也就少 7000 次確認；但只要有 1 次本來該 Deny 的你沒看到，損失可能抵消一年的省時。反覆確認不是目的；清楚範圍、保持備份、檢查結果才是目的。
