# 读者起点、讲解深度与信息密度

作者于2026-10-04明确要求，适用于AI教程工程的现有和后续图书、独立教程及其阅读派生版。它优先于旧模板中“所有按键首次解释”“每章必须三件套”等机械要求；单书已有更具体、且不冲突的读者约定继续有效。

## 从读者已有的能力出发

AI工具入门书默认读者有日常电脑使用经验，熟悉打开软件、复制粘贴、文件夹、保存和常见系统功能；不默认有目标产品、编程、终端或AI专业知识。非技术作品同样先明确本领域读者已知与未知，不套用电脑教程。

常见动作直接说“打开文件”“另存为”即可。产品特有入口、文件作用域、模式与权限等会影响成败的差别，要准确交代。一个操作即使使用常见按钮，只要在当前产品中有特殊后果，就解释这个后果。不能把“读者会用电脑”当成省略关键产品步骤的理由。

## 只留下值得学会的知识点

每个知识点都应解决读者的实际问题，帮助其行动、判断或迁移。有用就讲到读者能理解和使用；与任务无关、只够报一个名字或不值得细讲的内容，删掉或不引入。功能清单不能冒充教学，减少篇幅也不能省掉推理中间的一步。

“讲透”以使用需要为尺度：读者知道它是什么、为什么会影响眼前工作、该如何使用或判断结果，遇到一个相关变化仍知道怎么办。无需为办公使用补上模型数学或完整技术史。必要的适用条件、失败原因及替代做法属于有效信息，应随问题说明。

## 陌生概念在首次需要时解释

目标产品及AI专业词第一次进入读者的有效阅读路径时，用日常语言解释，并结合正在做的事说明作用。先给能理解的意思，再给名称；不要用另一串术语解释一个术语，不把必要说明推到后章或术语表。

定义无需每章重讲。按需选读章节可给一句够用提醒和明确回查入口，让独立阅读成立。缩写或英文界面词确需保留时说明中文含义及本次选择。读者已经能理解的日常词不重新写词典。

## 用场景教AI工作方法

除了点击和提示词，还要让读者理解关键决定：结果给谁用、材料凭什么可作依据、哪些步骤适合交给AI、哪里值得先检查、反馈怎样具体、变化影响哪些成果、哪些规则下次可复用。这些判断应在案例出现分歧、错误或变化时讲清，不另堆“AI思维”口号。

同一种方法在最合适的章节讲透，其他场景只补本场景的新条件。请求示例说明会随任务变化的内容，使读者能改用自己的材料。任务简单时允许直接完成，不强制所有工作都经过冗长计划、确认和复盘。

## 简洁与深入同时成立

删除常识铺垫、反复预告、同义结论、空泛劝告和为显得完整而增加的段落。保留具体事实、因果、操作、判断、例子与必要边界。复杂处可以长，浅显处及时停；不以短句数量、篇幅缩减或术语数量评价质量。

段落围绕一个意思展开，让读者顺着内容理解，无需从大量提醒和零碎清单中自行拼结论。小结、练习、排障是否单列取决于它是否提供额外帮助；已经在案例中完成的步骤不在章末整套重做。作者核验表、生产日志和重复免责声明不进入读者正文。

## 编辑复核与采用

逐章同时检查两端：有无需要读者猜的解释缺口；有无删掉也不损失理解的冗余。按章节用途检查有效知识、操作判断或迁移用法，不要求每章凑齐三者，也不强求统一栏目或字数。发现浅讲时，要么补上有用解释与例子，要么删除该知识点，不能只加一句“很重要”。

本规则作为全项目作者要求立即生效。新书模板保存离线快照；既有书由当前写入负责人在下一次编辑时显式同步规则、复核受影响正文，不由其他任务批量覆盖书稿。规则更新不代表旧正文已经通过复审，也不刷新产品事实、实测或试读状态。
